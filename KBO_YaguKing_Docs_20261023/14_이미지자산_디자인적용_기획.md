# 야구왕 — 이미지 자산 디자인 적용 기획

- 작성일: 2026-10-26 · 상태: **기획안** · 1·3단계 구현 완료(§8.1, §8.2)
- 요청: 프로젝트 폴더의 이미지를 활용해 게임 디자인에 적용할 수 있도록 기획
- 관계: 06 문서 §11 리스크 2(이미지 자산 전면 자체 제작), 08 문서 머리말·§2.5(구단 × 등급 테마)·§2.6(화면 스타일), 12 문서(데이터 권리)

---

## 0. 한 줄 결론

**폴더의 이미지 네 장은 게임에 그대로 넣지 않는다.** 두 장은 구단 공식 로고·마스코트와
타사(HAEGIN) 저작권 표기를 담고 있고, 나머지 두 장도 구단 상표를 흉내 낸 생성
이미지다. 대신 이미지에서 **보호 대상이 아닌 디자인 방향** — 수집 카드 형식, 장식
프레임의 격, 소재 질감, 큰 이니셜 타이포 — 을 뽑아, 이미 만든 **등급 7단계·구단
테마**에 연결한다. 결과물은 **"내 선수 카드"**와 **업적 카드 컬렉션**, 그리고 우리
**자체 마스코트**다. 모든 그림은 새로 만든다.

## 3. 이미지에서 가져올 것 — 방향만

아이디어와 스타일은 보호 대상이 아니다. **구체적인 그림을 베끼지 않고**, 방향만 가져온다.

| 이미지에서 본 것 | 가져올 방향 | 가져오지 않을 것 |
|---|---|---|
| 수집 카드 상자에 카드가 줄지어 놓인 구성 | **수집 카드 형식** — 모으고, 비교하고, 공유하는 단위 | 상자·띠 디자인, 배치 그대로 |
| 금박 장식 테두리 vs 은색 단정한 테두리 | **프레임의 격이 등급을 말한다** | 특정 테두리 문양 |
| 펠트·가죽·금속·대리석·석재 질감 | **소재로 격을 표현** (육성선수는 종이, 명예의 전당은 금속) | 같은 질감 사진 |
| 큰 이니셜 + 자수 같은 대학 스포츠 타이포 | **큰 이니셜 타이포** — 단, **사용자 닉네임 이니셜**에 쓴다 | 구단 이니셜 로고(D·L·K…) |
| 구단별 마스코트 캐릭터 | **캐릭터가 있는 게임** — 단, **우리 자체 캐릭터 하나** | 구단 마스코트 |

## 4. 우리 시스템에 대응시키기

새 시스템을 만들지 않는다. 이미 있는 두 축에 얹는다.

| 카드의 요소 | 연결되는 기존 시스템 |
|---|---|
| 프레임(테두리·소재·광채) | **등급 7단계** (08 문서 §2.5, `src/lib/theme/tiers.ts`) — 장식이 한 겹씩 늘어나는 구조가 그대로 프레임 단계가 된다 |
| 카드 바탕 | **구단 테마 띠** (`teamTheme`의 surface → surfaceAlt) — 구단 **색**만, 로고 없음 |
| 고대비 화면 | **화면 스타일** (08 문서 §2.6) — 고대비에서는 질감·광채를 빼고 단색 프레임 |
| 카드 글자 | 이미지에 굽지 않고 HTML로 — 대비·번역·화면 낭독 |

### 4.1 등급별 카드 프레임

| 등급 | 소재 | 프레임 | 장식 |
|---|---|---|---|
| 1 육성선수 | 무지 종이 | 얇은 선 | 없음 |
| 2 백업 | 크라프트지 | 구리빛 선 | 모서리 리벳 |
| 3 주전 | 코팅지 | 은색 이중선 | 모서리 장식 |
| 4 올스타 | 광택지 | 별빛 청 이중선 | 별 무늬 띠 |
| 5 골든글러브 | 금박 | 금색 테두리 | 글러브 실밥 무늬 |
| 6 MVP | 홀로그램 | 자수정 테두리 | 은은한 홀로 광택 |
| 7 명예의 전당 | 금속판 | 무지개 테두리(흐름) | 각인 + 광채 |

색은 이미 테스트로 대비를 고정한 등급색을 그대로 쓴다. 질감은 그 위의 장식층이다.

## 5. 적용 기능

### 5.1 내 선수 카드 — **1순위**

지금의 공유 카드(`/share/[id]`, OG 이미지)를 **수집 카드 형식**으로 고도화한다.
이미 기록을 만든 사람의 구단·등급으로 칠해지므로(08 문서 §2.5) 틀은 있다.

```
┌──────────────────────────┐  ← 등급 프레임 (5 골든글러브: 금박·실밥)
│ Lv.5 골든글러브     LG   │  ← 등급 배지 · 구단명(글자)
│                          │
│        ╔═══╗             │
│        ║ 운 ║             │  ← 닉네임 이니셜 큰 타이포 (구단 로고 아님)
│        ╚═══╝             │
│        운영자            │
│ ──────────────────────── │  ← 구단 테마 띠 바탕
│  타율 .308   OPS .779    │
│  타석 17     득점 1      │
│                          │
│  야구왕 · 2026 시즌      │
└──────────────────────────┘
```

- 그림 속 숫자는 형식을 보이기 위한 예시다
- 비율: 실물 트레이딩 카드와 같은 5:7 (공유 이미지는 OG 규격 1200×630에 카드를 얹은 구성)
- 카드 앞면 = 이번 경기, 뒷면(뒤집기) = 통산 기록 — 회원만
- 이미지로 굽는 것은 **프레임 장식과 질감뿐**. 글자는 HTML(웹) / Satori 텍스트(OG)

### 5.2 업적 카드 컬렉션 — 2순위

카드를 **모으는** 이유를 만든다. 업적마다 카드 한 장.

| 업적 | 조건 | 희귀도(프레임) |
|---|---|---|
| 첫 안타 | 첫 안타(1B·2B·3B·HR. 볼넷은 아니다) | 1 |
| 첫 홈런 | 첫 홈런 판정 | 2 |
| 5연속 정답 | 연속 정답 승급 보너스(`streak` 또는 `both`) 첫 발동 | 3 |
| 사이클링 히트 | 한 경기에서 1B·2B·3B·HR | 5 |
| 빅 이닝 | 한 이닝(같은 경기·같은 이닝)의 타점 합 5점 이상 | 6 |
| 명예의 전당 입성 | Lv.7 도달 | 7 |

- **변경 (2026-10-26, 3단계 구현)**: 초안의 "첫 안타 = 첫 출루"는 이름과 조건이 어긋나
  안타로 고쳤다. 희귀도 6의 "무결점 이닝(한 이닝 전 타석 출루)"은 **이닝제에서
  달성할 수 없어** "빅 이닝"으로 바꿨다 — 이닝은 3아웃으로만 끝나므로 한 이닝에
  아웃이 없을 수 없다(`src/lib/engine/session.ts`)

- 프레임 희귀도는 등급 프레임과 **같은 7단계 자산을 재사용**한다(자산 수가 늘지 않는다)
- 획득 판정은 이미 있는 타석 원장(`at_bats`)에서 계산한다. 새로 수집하는 정보는 없다
- 화면: 마이 탭 "컬렉션" — 획득 카드는 앞면, 미획득은 실루엣 + 조건

### 5.3 자체 마스코트 — 3순위

구단 마스코트 대신 **야구왕 고유 캐릭터 하나**. 어느 구단에도 속하지 않는다.

- 쓰임: 빈 상태("아직 기록이 없어요"), 온보딩 첫 화면, 홈런·사이클링 연출, 오류 화면
- 표정 세트: 기본·기쁨·놀람·아쉬움·응원 5종
- 구단 테마에 따라 **모자 색만** 바뀐다(구단 테마색 사용, 로고 없음)
- **경기 화면 타석 중에는 나오지 않는다** — 문제에 집중해야 하고, 첫 투구까지 0탭 원칙(08 문서 §3)

### 5.4 구단 선택 카드 — 4순위

`TeamPicker`를 카드 모양으로. **로고 없이** 구단명(글자) + 구단 테마 띠 + 공통 야구 모티프
(공·배트·다이아몬드 선화). 10개 구단이 같은 모티프를 쓰고 색과 이름만 다르다.

## 6. 자산 제작

### 6.1 자산 목록

| 자산 | 형식 | 변형 | 수량 |
|---|---|---|---|
| 등급 프레임 | SVG (장식) + 작은 질감 타일(WebP) | 다크·라이트, 고대비는 단색 SVG만 | 7 |
| 카드 뒷면 문양 | SVG | 다크·라이트 | 1 |
| 공통 야구 모티프 선화 | SVG | 색은 CSS 변수로 | 4~6 |
| 자체 마스코트 | SVG(권장) 또는 WebP | 표정 5 × 모자색은 CSS | 5 |
| 업적 카드 일러스트 | SVG | — | 업적 수만큼 (1차 6) |

SVG를 기본으로 하는 이유: 색을 CSS 변수로 바꿀 수 있어 **구단 10개 × 다크·라이트 ×
고대비를 자산 하나로** 소화한다. 래스터로 만들면 그 조합만큼 파일이 늘어난다.

### 6.2 제작 경로

| 경로 | 장점 | 확인할 것 |
|---|---|---|
| 디자이너 의뢰 (권장) | 저작권 귀속이 계약서로 명확 | 저작재산권 양도 또는 독점 이용 허락 범위, 2차 수정 권한 |
| 생성형 AI | 빠르고 싸다 | 서비스 약관의 **상업적 이용** 허용, 워터마크 정책(지우지 않는다), 결과물 권리 귀속 |

생성형 AI를 쓸 때 **프롬프트 금지어**: 구단명, 구단 로고·엠블럼·마스코트 이름, "KBO",
"프로야구 GO", 실존 선수 이름. 금지어를 넣으면 결과물이 그 표지를 닮게 된다 — 폴더의
생성 이미지 두 장이 바로 그 예다.

### 6.3 자산 권리 기록

문항의 `rights_note`와 같은 원칙. 자산마다 매니페스트에 출처를 남긴다.

```json
{ "path": "frames/tier-5.svg", "author": "〔디자이너명〕", "license": "저작재산권 양도 계약 2026-11-○○",
  "source": "의뢰 제작", "aiGenerated": false }
```

매니페스트에 출처가 없는 자산이 들어오면 **빌드가 실패**하게 한다(보안 점검 스크립트와 같은 방식).

## 7. 기술

- **위치**: `public/assets/` + 매니페스트. 파일명에 버전(`tier-5.v2.svg`)을 넣어 캐시 무효화
- **성능**: 랜딩(=첫 타석)에는 이미지 0개 — 첫 투구까지의 속도가 핵심이다. 카드 화면은
  지연 로딩. 카드 한 장의 자산 합계 60KB 이하
- **글자를 이미지에 굽지 않는다**: 대비 검사·고대비 스타일·화면 낭독이 모두 깨진다
- **대체 텍스트**: 카드 전체에 "운영자 선수 카드, 골든글러브 등급, 타율 .308"처럼 요약 하나.
  프레임·질감은 장식이므로 숨긴다(`aria-hidden`)
- **고대비 스타일**: 질감·광채·흐르는 무지개를 끄고 단색 프레임(08 문서 §2.6과 같은 원칙)
- **reduced-motion**: 카드 뒤집기·홀로 광택 애니메이션 정지
- **OG 이미지**: Satori는 SVG를 이미지로 넣을 수 있다. 프레임 SVG를 그대로 합성한다
  (숫자는 문자열로 넘긴다 — Satori는 0이 아닌 숫자 자식에서 실패한다. `tests/unit/share/opengraphImage.test.ts`가 지킨다)
- **테스트**: 매니페스트 검사(출처 없는 자산 0), 카드 컴포넌트의 등급 7 × 스타일 3 렌더,
  axe(카드 화면), 360px 가로 스크롤 0

### 8.1 1단계 구현 기록 (2026-10-26)

- **공유 화면** `/share/[sessionId]`: `src/components/share/PlayerCard.tsx`. 세 겹 구조 —
  등급 테두리(`.tier-frame`) › 소재(`.player-card__material[data-material]`) › 단색 면.
  소재는 테두리 여백에만 깔아 글자 대비에 끼어들지 않는다
- **소재 정의**: 등급 정의에 `material`을 붙였다(`src/lib/theme/tiers.ts`). 웹은
  `globals.css`의 그라데이션, OG는 `src/lib/theme/material.ts`의 Satori용 값(Satori는
  CSS 변수·`color-mix`를 모른다). 둘은 같은 의도를 다른 수단으로 옮긴 것이라
  픽셀까지 같지는 않다
- **OG 이미지**: 왼쪽에 득점 요약, 오른쪽에 같은 카드(384×538, 5:7). 리벳은 작은 원
  요소로, 명예의 전당 무지개 테두리는 바깥 면 칠하기로 그린다
- **가운데 글자**: 닉네임 첫 글자(그래핌 단위, 라틴 문자는 대문자). 장식이라 낭독에서 뺀다
- **고대비**: 소재 질감·홀로 흐름을 끄고 단색 면 + 등급색 실선
- **고친 것**: 실밥(점선)이 금박과 같은 색이라 묻혀서 바탕색 쪽으로 당겼다. 리벳이 둥근
  모서리에 잘려서 곡선이 끝난 자리로 옮겼다
- **테스트**: `tests/unit/share/playerCard.test.ts`(마크업·소재·첫 글자),
  OG 등급 7종 렌더, `tests/e2e/playerCard.spec.ts`(카드 표시·5:7·axe·320~1280px 가로
  스크롤·고대비). 고대비 규칙을 지우면 E2E가 실패하는 것을 확인했다
- **하지 않은 것**: 카드 뒷면(통산 기록), 뒤집기, 결과 화면 적용 — 2단계 이후

### 8.2 3단계 구현 기록 (2026-10-26)

- **판정**: `src/lib/achievements/rules.ts`의 순수 함수 `judgeAchievements`. 결과가 확정된
  타석을 **시간순**으로 한 번 훑어 처음 조건을 채운 타석의 제출 시각을 획득 시각으로 삼는다
- **조회**: `src/server/me/achievements.ts`. 본인 경기(`play_sessions.user_id`)의 확정 타석만
  읽는다. 모드·경기 상태는 가리지 않는다(기권한 경기의 홈런도 친 홈런이다). 획득일은 KST
- **저장하지 않는다**: 획득 테이블·마이그레이션이 없다. 원장이 진실이고, 규칙을 고치면 과거
  기록에도 다시 적용된다. 타석이 아주 많아지면 집계 테이블로 옮긴다
- **명예의 전당**: 레벨로 판정한다. 레벨에 오른 시각은 원장에 없어 획득일을 비운다(지어내지 않는다)
- **화면**: `/me/collection`(마이 탭). "내 기록 | 컬렉션" 전환 링크를 두 화면에 두었다.
  카드는 선수 카드와 같은 세 겹 프레임을 작게 쓴다(`.player-card--mini`). 미획득은 중립 종이 +
  점선 테두리 + "?" 표식이지만 **제목·조건은 그대로 읽힌다**(흐리게 하지 않는다)
- **고친 것**: 카드의 `overflow: hidden`을 `clip`으로 바꿨다. hidden이면 5:7 비율의 자동 최소
  높이가 사라져 글자를 키울 때 내용이 잘린다
- **테스트**: 규칙 단위 19개(`tests/unit/achievements/rules.test.ts`), 통합 6개(본인 기록만,
  미확정 타석 제외, KST 날짜, 사이클·빅 이닝, 명예의 전당). 비로그인 접근 시 로그인 화면으로
  보내는 E2E. 로그인 상태 화면은 브라우저에서 확인했고 axe 위반 0(다크·라이트·고대비, 375px)
- **하지 않은 것**: 획득 순간 알림(경기 결과 화면 연출), 공유, 업적 일러스트 — 자산·4단계 이후

## 10. 폴더 이미지 처리 권고

- **저장소에 커밋하지 않는다.** 지금은 추적되지 않은 상태지만 `.gitignore`에 규칙이 없어,
  `git add -A` 한 번이면 타사 저작권 표기가 든 이미지가 저장소에 들어간다. 저장소를
  공유하거나 공개하면 그 자체가 배포가 된다
- 참고 자료로 남기려면 저장소 밖으로 옮기거나 `design-refs/` 폴더로 모으고 그 폴더를
  `.gitignore`에 넣는다 — **사용자 결정 사항이라 옮기지 않았다**
- 디자이너나 AI에 참고 자료로 넘길 때는 "**이 그림을 베끼지 말고, 수집 카드 형식과
  프레임의 격이라는 방향만**"이라고 명시한다
