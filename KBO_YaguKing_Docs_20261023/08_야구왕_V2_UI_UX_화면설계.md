## 2. 디자인 시스템

### 2.1 색 토큰

다크를 기본으로 정의하고 라이트를 파생한다. 모든 상태는 **색 + 아이콘 + 텍스트** 3중 표기한다.

| 토큰 | 다크 | 라이트 | 용도 |
|---|---|---|---|
| `--bg-base` | `#0C1117` | `#F7F8FA` | 페이지 배경 |
| `--bg-field` | `#10251A` | `#E8F2EB` | 스코어보드·그라운드 영역 |
| `--bg-card` | `#161D26` | `#FFFFFF` | 카드 |
| `--ink-1` | `#F2F5F7` | `#101418` | 본문 |
| `--ink-2` | `#9AA6B2` | `#5C6873` | 보조 텍스트 |
| `--line` | `#243040` | `#DDE3E9` | 구분선 |
| `--accent` | `#FFC53D` | `#856404` | 브랜드·CTA(전광판 앰버) |
| `--on-base` | `#35B36B` | `#1E7A46` | 출루·안타 |
| `--out` | `#E8636F` | `#C0392B` | 아웃 |
| `--hr` | `#FF8A3D` | `#A8490F` | 홈런 |
| `--focus` | `#5AB0FF` | `#0B63CE` | 포커스 링 (3:1 이상) |

대비 기준: 본문 4.5:1, 큰 텍스트·아이콘 3:1 이상(WCAG 2.2 AA). `--accent` 위 텍스트는 다크에서 `#101418`, 라이트에서 `#FFFFFF`.

> **이 표의 값은 단위 테스트로 고정되어 있다**(`tests/unit/design/contrast.test.ts`).
> 테스트가 `globals.css`에서 토큰을 직접 읽어 실제로 쓰는 조합의 대비를 계산한다.
> 초안의 라이트 `--accent #B8860B`(3.25:1), 라이트 `--hr #D2691E`(3.63:1),
> 다크 `--out #E05260`(4.48:1)은 AA 미달이어서 위 값으로 교체했다.
> axe는 렌더된 화면만 보므로 토큰 검사를 함께 둔다.

### 2.3 간격·형태·터치

8px 그리드. 카드 radius 16, 보기 버튼 radius 12. 터치 타깃 **주 버튼 56px / 보조 44px**. 보기 버튼 간 간격 최소 8px(오탭 방지). `env(safe-area-inset-bottom)` 반영.

### 2.4 모션 예산

| 구간 | 시간 | reduced-motion |
|---|---|---|
| 제출 → 서버 응답 대기 | 목표 p95 300ms, 버튼 잠금 + 인라인 스피너 | 동일 |
| 판정 공개(정답/오답 표시) | 150ms 페이드 | 즉시 |
| 결과 배지 등장(`2루타`) | 250ms 스케일 | 즉시 |
| 주자 이동 | 400ms 이징 | **즉시 상태 전환** |
| 다음 타석 자동 전환 | 총 **1.6초** 후 | 동일(자동 전환 유지) |
| 홈런 연출 | 900ms (1회, 반복 없음) | 정적 배지로 대체 |

`prefers-reduced-motion: reduce`에서는 모든 이동·스케일·플래시를 제거하고 상태만 바꾼다. 점멸(flash) 효과는 어떤 모드에서도 사용하지 않는다.

### 2.5 테마 — 구단 × 등급 (2026-10-24 추가)

두 축을 **분리한다.** 구단은 색조를, 등급은 장식의 격을 바꾼다. 서로 덮어쓰지 않는다 — LG 팬이 MVP 등급이어도 강조색은 LG 색이고, 등급은 배지와 테두리로 드러난다.

**구단 테마가 바꾸는 것**: `--accent`, `--accent-ink`, 구단 띠(`--team-surface`, `--team-surface-alt`).
**절대 바꾸지 않는 것**: `--on-base`, `--out`, `--hr` 같은 의미 색. 판정을 전달하고 대비를 따로 맞춰 둔 색이다. 경기 중 남은 시간 막대도 촉박해지면 구단색이 아니라 `--out`으로 바뀐다.

**색을 손으로 고르지 않는다.** 구단을 연상시키는 기준 색에서 OKLCH 명도만 움직여 AA를 만족하는 가장 가까운 값을 도출한다(`src/lib/theme/`). 색상각은 지킨다(±20° 이내, 테스트로 고정). 10개 구단 × 라이트/다크 × 쓰임새를 전부 테스트가 검사한다.

| 쓰임새 | 기준 |
|---|---|
| 강조색을 글자로 (카드·페이지 위) | 4.5:1 |
| 강조색 버튼 위 글자 | 4.5:1 |
| 구단 띠 양 끝의 본문·보조 글자 | 4.5:1 |
| 띠 위 강조색 경계(왼쪽 막대, 선택 테두리) | 3:1 |

**등급 장식은 누적된다.**

| 등급 | 장식 | 색 |
|---|---|---|
| 1 육성선수 | 외곽선 배지 | 중립(보조 글자색) |
| 2 백업 | 채운 배지 | 구리빛 동 |
| 3 주전 | + 카드 테두리 | 은 |
| 4 올스타 | + 카드 테두리 | 별빛 청 |
| 5 골든글러브 | + 광채 | 금 |
| 6 MVP | + 광채 | 자수정 |
| 7 명예의 전당 | + 무지개 테두리(천천히 흐름) | 금·장미·자수정·하늘 |

등급색은 서로 다른 색상에서 고른다. 같은 계열이면 다크에서 명도를 올리는 순간 구분되지 않는다. 실제로 처음 고른 동색은 라이트 모드에서 금을 어둡게 한 색과 거의 같은 갈색(ΔE 0.049)이 되어 구리 쪽으로 옮겼다. 이웃 등급 간 ΔE 0.08 이상을 테스트로 고정한다. 무지개 테두리의 흐름은 `prefers-reduced-motion`에서 멈춘다.

**자동 적용 규칙** (`src/server/theme/context.ts`)

| 상황 | 구단 | 등급 |
|---|---|---|
| 비회원 | 브랜드 기본(잔디·노랑) | 없음 |
| 회원, 대표 구단 없음 | 브랜드 기본 | 내 등급 |
| 회원, 대표 구단 있음 | 내 구단 | 내 등급 |
| 공유 카드 · OG 이미지 | **기록을 만든 사람의** 구단 | 만든 사람의 등급 |
| 랭킹 각 행 | **그 선수의** 구단 | 그 선수의 등급 |
| 온보딩·설정에서 구단 선택 | 고르는 순간 미리보기 | — |
| `TEAM_THEMES=off` | 브랜드 기본 | 유지 |

공유 카드에서 "나도 1이닝 해보기" 버튼은 보는 사람에게 하는 말이라 바깥(보는 사람의) 테마를 쓴다. 범위를 좁혀 다시 칠할 때는 구단이 없더라도 브랜드 값을 **명시적으로** 넣는다 — 일부만 넣으면 CSS 변수가 상속되어 바깥 구단색이 새어 든다.

모바일 주소창 색(`theme-color`)도 구단 띠 색을 따른다.

### 2.6 화면 스타일 — 사용자가 고른다 (2026-10-24 추가)

성별 테마 요청이 있었으나 **성별을 수집하지 않고**, 사용자가 설정에서 직접 고르는 스타일로 대신했다. 성별로 색을 나누면 새 개인 정보를 모아야 하고(처리방침 범위 확대), 사용자를 고정관념으로 묶게 된다.

| 선택 | 내용 | 기준 |
|---|---|---|
| 자동 | 기기의 '대비 높이기' 설정이 켜져 있으면 고대비, 아니면 기본 | — |
| 기본 | 야간 전광판 | 본문 4.5:1 |
| 부드러운 | 따뜻한 바탕, 덜 눈부신 흰 글자, 둥근 모서리(카드 22px), 옅은 광채 | 본문 4.5:1 |
| 고대비 | 순흑·순백 바탕, 또렷한 테두리(3:1), 두꺼운 포커스 링(4px) | **본문 7:1 (AAA)** |

**저장**: 기기별 쿠키(`yk_style`) 하나. 서버 DB에는 남기지 않는다 — 수집 항목이 늘지 않고 내보내기·삭제 범위도 바뀌지 않는다. 쿠키라서 서버가 첫 화면부터 바로 그린다(깜빡임 없음). 기존 클래식 모드(브라우저 저장소)와 같은 "기기 편의 설정" 원칙이다.

**자동**은 쿠키가 없을 때의 기본값이다. 고대비는 접근성 기능이라 설정 화면을 찾지 못한 사람에게도 적용되어야 한다. 기기 설정은 브라우저만 알므로 `<head>`의 짧은 스크립트가 **그리기 전에** 정한다(하이드레이션 뒤에 바꾸면 고대비가 필요한 사람에게 첫 화면이 한 번 기본 대비로 보인다). 기기 설정이 바뀌면 따라가고, 직접 고른 값이 있으면 손대지 않는다.

**구단·등급색과의 관계**: 기본과 부드러운은 같은 구단·등급색을 쓴다 — 두 스타일의 표면을 **모두** 상대로 4.5:1을 맞춰 도출한다. 고대비는 7:1로 따로 도출한다(4.5:1 구단색을 그대로 두면 고대비라 부를 수 없다). 스타일 3종 × 라이트/다크 × 구단 10개 + 등급 7개를 테스트가 전부 검사한다.

**고대비의 장식 조정**: 구단 띠는 그라데이션 대신 단색, 광채 제거, 테두리 3px, 명예의 전당의 흐르는 무지개는 멈추고 배지는 7:1 단색(무지개 각 색 위에서 작은 글자 7:1을 모두 맞출 수 없다).

**명시도 주의**: 스타일 블록(`:root[data-style='soft']`)이 `<html>`의 구단 규칙보다 명시도가 높으면 부드러운 스타일에서 구단 강조색이 브랜드 기본색으로 덮인다. 구단 규칙에 `:root[data-team]`을 더하고 스타일 블록 뒤에 둔다. 테스트가 순서를 고정한다.

**알려진 한계**: 설정 화면은 회원 전용이라 비회원은 직접 고를 수 없고 '자동'만 적용된다. 비회원도 고르게 하려면 경기 화면이나 랜딩에 진입점이 필요하다.

## 3. V01 `/` — 랜딩 = 1번 타석

**원칙: 첫 투구까지 0탭.** 히어로 자리에 로그인·약관·튜토리얼·모달을 두지 않는다.

- 서버가 첫 방문에 게스트 세션을 만들고 **1번 타석 문항을 서버 렌더로 즉시 표시**한다.
- 타이머는 **첫 보기를 탭하거나 키를 누르는 순간이 아니라 문항 노출(`opened_at`) 시점**부터 흐른다. 따라서 상단에 "15초" 안내를 미리 보여주고, 첫 타석에만 **3초 카운트다운**(`3 · 2 · 1 · 플레이`)을 준다.
- 하단에 작은 보조 링크: `로그인`, `규칙 보기`, `랭킹 구경하기`. 가입 CTA는 **플레이 전에 노출하지 않는다.**
- 재방문 비회원: "오늘 체험 1이닝이 남았습니다" 를 **시작 전에** 표시. 0회 남으면 V01이 V03 가입 게이트 요약으로 대체된다(`GUEST_TRIAL_EXHAUSTED`).
- 로그인 회원이 `/`에 오면 V06 대시보드로 리다이렉트한다.

상태: 로딩(문항 스켈레톤) / 정상 / 문항 공급 실패(대체 문항 또는 재시도) / 오프라인 / 체험 소진.

| 영역 | 내용 |
|---|---|
| 헤더 | `나가기`(확인 다이얼로그), 이닝 표시 `1회 ▲`, 현재 득점 |
| 스코어보드 | 아웃 카운트 `●●○`, **주자 다이아몬드**, 연속 정답 배지 |
| 문제 메타 | 카테고리 · 난이도 · **기록 기준일**(필수 표기) |
| 문제 카드 | 문항 본문 |
| 타이머 | 숫자 + 진행 바 동시 |
| 보기 | A/B/C/D, 2×2 그리드 |
| 판정 오버레이 | 결과 배지 + 정답 1줄 + `해설 자세히` |

주자 다이아몬드는 `◆`(주자 있음) / `◇`(없음)으로 **도형 차이까지 둔다**. 색만으로 구분하지 않는다.

### 4.2 타석 상태 머신 (화면)

```text
COUNTDOWN(첫 타석만, 3s)
   ↓
AT_BAT_ACTIVE ──── 보기 탭/키 입력 ───→ SUBMITTING(버튼 잠금)
   │                                        ↓
   │ 15초 경과                        RESOLVED(판정 공개 → 주자 이동)
   ↓                                        ↓
TIMEOUT(루킹 삼진) ───────────────→ 아웃 +1
                                            ↓
                              ┌── 아웃 3 ──→ INNING_END → (목표 이닝 초과) FINISHED
                              └── 그 외 ──→ 다음 타석(1.6s 후 자동) → AT_BAT_ACTIVE
```

- `SUBMITTING` 중에는 **네 개 보기 전부 비활성**하고 선택한 보기에만 스피너를 둔다. 0.4초 내 재입력은 무시한다.
- 서버 응답이 1.5초를 넘으면 "판정 확인 중" 문구로 전환하고, 실패 시 **자동 재시도 대신 `GET /play/sessions/{id}`로 확정 여부를 먼저 조회**한다(중복 타석 방지).
- 타이머가 0이 되어도 **화면 판정은 임시**다. 서버 응답이 최종이며, 불일치 시 서버 값으로 덮어쓰고 "서버 기준으로 처리되었습니다"를 1회 고지한다.

### 4.3 판정 오버레이

결과별 표기 — **배지 텍스트가 1차 정보이고 색은 보조**다.

| 결과 | 배지 | 아이콘 | 색 | 연출 |
|---|---|---|---|---|
| HR | `홈런!` | ⚾ | `--hr` | 900ms 1회, 주자 전원 홈 |
| 3B | `3루타` | → | `--on-base` | 주자 전원 홈 |
| 2B | `2루타` | → | `--on-base` | 2베이스 이동 |
| 1B | `안타` | → | `--on-base` | 1베이스 이동 |
| BB | `볼넷` | ◦ | `--on-base` | 강제 진루만 |
| K | `삼진 · 아웃` | ✕ | `--out` | 아웃 카운트 증가 |
| 시간초과 | `루킹 삼진 · 아웃` | ✕ | `--out` | 동일 |

승급 발생 시 배지 아래에 사유를 한 줄로 밝힌다 — `고급 문항 보너스 · 한 단계 상승` 또는 `5연속 정답 보너스 · 한 단계 상승`. 보너스가 왜 생겼는지 모르면 학습이 일어나지 않는다.

오답일 때는 **정답 보기를 강조 표시**하고 한 줄 정답 설명을 띄운다. 전체 해설·출처는 `해설 자세히`를 누를 때 펼치며, **누르는 즉시 1.6초 자동 전환 타이머가 멈춘다**(읽는 중 넘어가지 않게). 닫으면 `다음 타석` 버튼으로 수동 진행한다.

### 4.4 이닝 교대 / 종료

- 3아웃 시 `1회 종료 · 3득점` 인터스티셜 1.2초. 다음 이닝이 있으면 주자·아웃 초기화를 **시각적으로 보여준 뒤** 다음 타석으로 간다.
- 목표 이닝을 넘기면 V03으로 **자동 이동**한다(사용자 탭 요구 없음).
- `나가기`는 확인 다이얼로그 → `POST /play/sessions/{id}/abandon`. "지금까지 기록은 남지만 공식 집계에는 들어가지 않습니다"를 명시한다.

### 4.5 상태·예외 매트릭스

| 상황 | 화면 처리 |
|---|---|
| 새로고침 / 탭 복귀 | `GET /play/sessions/{id}`로 스코어보드·현재 타석·남은 시간 복원 |
| 제출 후 새로고침 | 이미 확정된 타석은 결과 상태로 복원, **중복 제출 생성 금지** |
| 오프라인 | 상단 배너 + 보기 비활성, 복귀 시 즉시 상태 재조회 |
| `SEQUENCE_MISMATCH` | 서버 현재 타석으로 화면 동기화 후 안내 1회 |
| `ANSWER_DEADLINE_EXCEEDED` | 해당 타석 아웃 확정 표시 후 진행 |
| `SESSION_FINISHED` | V03으로 이동 |
| 세션 만료 | "경기가 종료되었습니다" + 새 경기 CTA |
| 문항 로드 실패 | 타석 보류 + 재시도. 3회 실패 시 세션 중단 안내 |

## 5. V03 `/play/[sessionId]/result` — 결과 + 가입 게이트 (핵심)

### 5.1 노출 원칙

**박스스코어는 비회원에게도 전부 공개한다.** 결과를 인질로 가입을 요구하지 않는다. 가입은 "저장·적립·구단 반영"의 대가로만 요청한다.

### 5.2 영역 순서 (위 → 아래)

1. **최종 스코어** — `최종 3득점`, 이닝/아웃 요약.
2. **박스스코어 카드** — 타석(PA) · 타수(AB) · 안타(H) · 2루타 · 3루타 · 홈런 · 볼넷 · 삼진 · 타율 · OPS. 숫자는 tabular-nums.
3. **타석 로그** — 순번 / 결과 / 응답시간 / 카테고리 / 정답 여부. 각 행을 펼치면 해설·출처(V1 출처 표기 원칙 승계).
4. **가입 게이트** — §5.3.
5. **다음 행동** — `한 이닝 더`, `공유`, (회원) `약점 코스 훈련`.

회원에게는 4번 자리에 **적립 결과**가 온다 — `통산 타율 .327 → .331`, 획득 XP, 등급 진행 바, 그리고 공식 경기면 `오늘 우리 구단 기여: 1/3이닝`.

### 5.3 가입 게이트

P1은 **G1 단독**으로 운영한다. G2·G3는 해당 기능(P2)과 함께 켠다.

| ID | 제목 | 본문 | 액션 |
|---|---|---|---|
| **G1** | `아직 저장되지 않았습니다` | "이 7타석은 임시 기록입니다. 저장하면 통산 타율에 적립되고 다음에 이어서 쌓입니다." | `3초 만에 저장하기` + 소셜 버튼(카카오/구글) |
| **G2** (P2) | `어느 구단에도 반영되지 않았습니다` | 오늘 대진표 + `내 기여 0 PA` | `구단 고르고 반영하기` |
| **G3** (P2) | `전적이 기록되지 않았습니다` | 승패는 표시, 전적은 `-` | `복수전 링크 만들기` |

게이트 카드 규칙:
- 카드이며 **모달이 아니다.** 화면을 덮지 않고, 닫기 버튼으로 접을 수 있으며, 접어도 다른 모든 기능은 동작한다.
- 숫자를 그대로 쓴다 — "기록을 저장하세요"보다 **"3안타 1홈런, 타율 .500을 저장하세요"**.
- P2 이후 스카우팅 리포트 블러 미리보기를 G1에 함께 붙인다(`컨택 60`, `주력 65`만 공개, 나머지 3개 블러).
- **금지**: 전면 모달, 닫기 없는 레이어, 가짜 카운트다운("30초 안에 가입"), 결과 가림, 1문제 후 가입 요구.

### 5.4 가입 직후 (승계 피드백)

OAuth 복귀 시 원래 세션·링크를 보존하고, V03으로 되돌아와 **1초 안에 보상을 보여준다**.

```text
✓ 기록이 통산에 적립되었습니다
   7타석 6타수 3안타 1홈런 — 통산 타율 .500
   다음 → [ 대표 구단 고르기 ]
```

승계 실패(만료·이미 승계)는 오류처럼 보이지 않게 처리한다 — "이미 저장된 기록입니다"로 안내하고 대시보드로 보낸다.

### 5.5 공유 카드

- OG 이미지 1200×630, 서버 생성. 내용: **닉네임 · 등급 · 박스스코어 핵심 3지표 · 1이닝 요약**.
- 노출 금지: 이메일, 실명, 정확한 플레이 시각, 문항 본문·정답(문제 유출 방지).
- `Web Share API` 우선, 미지원 시 링크 복사. 카카오 공유 SDK는 **사용 조건·키 확인 후** 적용(V1 보류 항목 승계).

게이트 카드에 **닫기(✕)가 있다.** 닫으면 `한 이닝 더`로 계속 플레이할 수 있고, 체험 잔여 횟수가 0이면 그 자리에서 잔여 안내로 바뀐다.

### 6.6 V03 결과 화면 — `md` / `lg`

`md` 2열: 좌측에 스코어 + 박스스코어, 우측에 타석 로그. 게이트 카드는 **2열 아래 전체 폭**으로 배치해 시선 종착점에 둔다.

```text
┌───────────────────────────┬──────────────────────────────┐
│  최종 3득점               │  타석 로그                   │
│  ┌── BOX SCORE ────────┐  │  1 → 2루타  3.4s  한국시리즈 │
│  │ PA 7  AB 6  H 3     │  │  2 ✕ 삼진   7.1s  선수기록   │
│  │ HR 1  BB 1  SO 3    │  │  3 → 안타   5.0s  구단역사   │
│  │ 타율 .500 OPS 1.250 │  │  ...                         │
│  └─────────────────────┘  │                              │
├───────────────────────────┴──────────────────────────────┤
│ ╔══ 아직 저장되지 않았습니다 ═══════════════════════╗ ✕  │
│ ║ 3안타 1홈런, 타율 .500  [ 3초 만에 저장하기 ]      ║    │
│ ╚═══════════════════════════════════════════════════╝    │
├──────────────────────────────────────────────────────────┤
│ [  한 이닝 더  ]   [  공유  ]   [  랭킹 보기  ]          │
└──────────────────────────────────────────────────────────┘
```

`lg`: 위 2열 중앙 정렬(최대 1040px) + 우측에 **공유 카드 실시간 미리보기**를 추가해 공유 전환을 끌어올린다.

### 6.7 V06 대시보드 "덕아웃" — 브레이크포인트 요약

| | `sm` | `md` | `lg` |
|---|---|---|---|
| 상단 | 닉네임·등급·XP 바 | 좌측 카드 | 좌측 사이드바로 이동 |
| 1순위 CTA | `오늘의 공식 3이닝` 전체 폭 | 2열 중 큰 카드 | 중앙 히어로 |
| 카드 | 1열 스택: 팬 리그 → 통산 성적 → 약점 코스 → 고스트 | 2열 그리드 | 3열 그리드 |
| 하단 | 탭 4개(홈/경기/랭킹/마이) | 탭 유지 | 사이드바 |

### 6.8 공통 반응형 요건

- **360px에서 가로 스크롤 0.** 보기 텍스트는 말줄임 대신 줄바꿈(카드 높이 증가 허용).
- 긴 구단명·닉네임은 2줄까지 허용하고 그 이상만 말줄임.
- 이미지 없이 레이아웃이 성립해야 한다(로고·사진 권리 미확보 전제).
- `md` 이상에서도 **단일 화면 입력 영역은 720px을 넘기지 않는다** — 보기 버튼이 너무 넓어지면 조준이 어려워진다.
- 성능 **목표**(실측 아님): LCP 2.5s, 타석 제출 p95 300ms, 일반 API p95 500ms.

## 7. 주요 화면 보조 명세

### V04 `/auth`
실제 설정 완료된 공급자만 노출. 소셜 버튼이 1차, 이메일은 접힌 보조 옵션. **약관·개인정보 동의는 분리 체크**로 버튼 바로 위 1줄 + 링크. OAuth 리다이렉트 시 `returnTo`(원래 결과 화면·고스트 링크)와 게스트 토큰을 보존한다. 중복 계정·취소·실패를 각각 다른 문구로 안내한다.

### V05 `/onboarding` (2단계)
1. **닉네임** — 자동 추천값 프리필(중복 회피 완료 상태), 그대로 `다음` 가능. 2~16자.
2. **대표 구단 1개** — 10개 구단 텍스트 칩 그리드(`sm` 2열 / `md` 3열 / `lg` 5열). "팬 페넌트레이스에 이 구단으로 참가합니다. 변경은 다음 날부터 적용됩니다"를 **선택 전에** 고지.

선수 선호·추가 구단은 이 흐름에 없다(V17 설정에서). 완료 후 **원래 결과 화면으로 복귀**해 적립을 보여주고, 복귀 지점이 없으면 V06으로 보낸다.

### V08 `/me/batting`
통산/시즌 토글. 박스스코어 테이블 + 추이 그래프(최근 10경기 타율). 누적 **30타석 도달 시** "시범경기 종료 — 스카우팅 리포트가 공개되었습니다" 인터스티셜 1회 + V09 이동 CTA. 50타석 미만은 비율 지표 랭킹 제외를 명시.

### V09 `/me/scouting` (P2)
5툴 `20~80` 바 차트 + 종합(OFP) 배지. 표본 부족 툴은 `관찰중`으로 회색 처리하고 남은 타석 수를 보여준다. 아래에 **존 맵 3×3**:

```text
          시대 →
        82-99  00-14  15-현재
고급  [  23%  ][ 41% ][  55%  ]   ← 약점 칸 테두리 강조 + "약점" 라벨
중급  [  52%  ][ 68% ][  74%  ]
초급  [  71%  ][ 85% ][  88%  ]
        ↑ 난이도
  [ 이 코스 집중 훈련 (5타석) ]
```

칸은 색 농도 + **숫자 + 약점 라벨**을 함께 쓴다(색만으로 구분 금지). 스크린리더는 각 칸을 "1982–1999 고급, 정답률 23퍼센트, 약점"으로 읽는다.

### V11 `/fan-league` (P2)
오늘 대진 카드(구단명 텍스트 + 중립 칩, OPS, 참가 팬 수, 상태) → 순위표(승·패·무·무효·승률·게임차). `내 구단` 고정 영역에 `오늘 기여 n/3이닝`과 `지금 1이닝 더하기` CTA. 최소 참가 팬 수 미달은 **"리그 준비 중"**으로, 무효 경기는 `NC`로 표기하고 승률 계산 제외를 각주로 명시. 집계 기준 시각과 **구단 변경 소급 미반영**을 화면에 상설 고지.

### V12 `/ghost/[token]` (P2)
도전장 카드: 보낸 사람 닉네임·등급·**득점만**(문항 목록·정답 절대 비노출). `도전 시작` 1탭으로 즉시 V02 진입(비회원도 가능). 만료 링크는 `CHALLENGE_EXPIRED` 안내 + 새 경기 CTA. 같은 회원 재응시는 "이번 기록은 전적에 반영되지 않습니다"를 **시작 전에** 알린다.

### V13 `/ghost/[token]/result` (P2)
좌우 분할 박스스코어 + 타석별 대조(같은 문항이므로 1:1 비교 가능). 승패 배지. 회원은 `복수전 링크 만들기`, 비회원은 G3 게이트.

### V15 `/rankings`
탭 3개: **비율(통산 OPS, 최소 50타석)** / **볼륨(시즌 누적 득점)** / **구단(팬 리그 승률)**. 내 순위 고정 영역. 각 탭에 산출 기준·집계 시각·최소 조건을 명시. RP 탭은 P3 전까지 노출하지 않는다.

### V17 `/settings`
프로필·대표 구단(변경 시 익일 적용 고지)·선호 선수·알림·**클래식 모드 토글**(점수제 표기)·해설 머무르기·데이터 내보내기·계정 삭제·개인정보 처리방침.

### V19 `/admin`
V1 S20 명세 승계 + V2 추가분: 자동 생성 문항 **승인 큐**(승인 없이는 `daily_feature_questions` 편성 불가), 팬 리그 집계 재계산·무효 처리, 게스트 승계 이상 로그, 응답시간 이상 분포 탐지 목록. 관리자 역할은 서버 검증(`user_metadata` 신뢰 금지).

## 8. 접근성

### 8.1 키보드

| 키 | 동작 |
|---|---|
| `1`~`4` / `A` `S` `D` `F` | 보기 선택(즉시 제출) |
| `Enter` | 다음 타석 / 해설 닫기 |
| `Space` | 해설 펼치기·접기 |
| `Esc` | 나가기 확인 다이얼로그 |
| `Tab` | 헤더 → 스코어보드 → 문제 → 보기 A~D → 보조 액션 |

보기 선택이 **즉시 제출**이므로 오입력 방지가 중요하다. 선택 직후 0.4초 입력 잠금을 두고, 키보드 사용자에게는 포커스된 보기에 `선택하면 바로 제출됩니다` 힌트를 노출한다.

### 8.2 스크린리더

- 스코어보드 변화는 `aria-live="polite"`로 고지: **"아웃 2, 주자 2루, 득점 3"**.
- 판정은 `role="status"`로: **"2루타. 정답 C. 고급 문항 보너스로 한 단계 상승."**
- 타이머는 `aria-live` **금지**(1초마다 읽히면 사용 불가). 대신 10초·5초·3초 남음만 고지한다.
- 보기 버튼 레이블: `"보기 A. <본문>"`. 문제 본문은 `aria-labelledby`로 연결.
- 다이아몬드는 장식이 아니라 정보이므로 `img` + `alt="주자 2루"`가 아닌 **텍스트 상태 요약**을 함께 둔다.

### 8.3 기타

- 모든 상태를 색 + 아이콘 + 텍스트 3중 표기. `안타`/`아웃`은 반드시 글자로 존재.
- 포커스 링은 배경과 3:1 이상, `:focus-visible` 사용.
- `prefers-reduced-motion`에서 주자 이동·홈런 연출 제거(§2.4).
- 다크/라이트 모두 AA 대비 검증. 다크를 기본으로 하되 시스템 설정을 따른다.
- 터치 타깃 44px 이상, 주 버튼 56px. 인접 타깃 간 8px 이상.
- 글자 크기 200% 확대와 `text-spacing` 조정에서 레이아웃이 깨지지 않아야 한다.

## 9. 상태 표준 (전 화면 공통)

모든 데이터 화면은 5상태를 갖는다 — **로딩 / 정상 / 비어있음 / 오류 / 권한 없음**. 추가로 경기 화면은 **오프라인 / 복원 중 / 만료**를 갖는다.

| 상태 | 표현 | 회복 경로 |
|---|---|---|
| 로딩 | 스켈레톤(스피너 단독 금지) | — |
| 비어있음 | 무엇을 하면 채워지는지 + CTA 1개 | 행동 유도 |
| 오류 | 사람이 읽을 문구 + `requestId` 접힌 영역 | 재시도 |
| 권한 없음 | 비공개 사유 설명 | 로그인 또는 뒤로 |
| 오프라인 | 상단 배너 + 입력 비활성 | 복귀 시 자동 재조회 |
| 복원 중 | "경기 상태를 불러오는 중" | `GET state` 완료 |

타인 프로필 방문 시 비공개 통계·오답·계정 정보는 **존재 여부도 노출하지 않는다**(V1 원칙 승계).
