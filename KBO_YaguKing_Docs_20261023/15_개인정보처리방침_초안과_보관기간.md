- 작성일: 2026-10-26 · 상태: **초안 — 법률 검토 전, 시행 전**
- 관계: 11 문서 §2.1(처리방침이 노출을 막는 첫째 항목), 06 문서 §12 리스크 8(미성년자 개인정보)

## 0. 한 줄 결론

처리방침 **초안**을 쓰고, 보관 기간을 정하고, **그 기간이 실제로 지켜지도록**
코드를 맞췄다. 처리방침에 쓴 기간은 전부 자동 삭제로 뒷받침된다. 만 14세 미만
가입 제한도 화면 문구가 아니라 서버에서 막는다. 남은 것은 **운영 주체 정보로
빈칸을 채우는 일과 법률 검토**다 — 사람이 할 일이다.

## 1. 무엇을 처리하는가 (코드에서 확인한 사실)

| 구분 | 항목 | 저장 위치 |
|---|---|---|
| 회원 | 이메일 | `auth.users` |
| 회원 | 닉네임, 대표 구단, 만 14세 확인 시각 | `profiles` |
| 회원(소셜) | 공급자 계정 식별자·이메일, 공급자가 보낸 이름·사진 주소 | `auth.identities` |
| 회원 활동 | 경기·타석 기록, 통산 성적, XP·등급, 랭킹, 존 집계 | `play_sessions`, `at_bats`, `user_batting_stats`, `user_private_stats`, `xp_transactions`, `leaderboard_entries`, `user_zone_cells` |
| 비회원 | 게스트 토큰 **해시**, 체험 일자·횟수, 체험 경기 기록 | `guest_sessions`, `play_sessions`, `at_bats` |
| 자동 | 접속 주소·시각·행위(로그인 기록) | `auth.audit_log_entries` |
| 자동 | 로그인 세션(접속 주소·브라우저 정보) | `auth.sessions`, `auth.refresh_tokens` |
| 자동 | 접속 주소의 **HMAC 값**(되돌릴 수 없음) | `rate_limit_counters` |

받지 않는 것: 이름, 생년월일, 전화번호, 성별, 결제 정보. 광고·분석 추적 도구도 없다.
`growth_events`는 테이블만 있고 0행이다(이벤트 적재는 보류 중).

## 2. 보관 기간 — 정한 값과 이유

단일 출처: `src/lib/privacy/retention.ts`. 삭제: DB 함수 `public.purge_expired_personal_data()`(0016).

| 대상 | 기간 | 이유 |
|---|---|---|
| 회원 정보·활동 기록 | **탈퇴 시까지, 탈퇴 즉시 파기** | 서비스의 본체다. 탈퇴 경로는 이미 있고(설정 › 계정 삭제) `auth.users`부터 CASCADE로 지워진다. 2023년 개정으로 "1년 미이용 시 파기(유효기간제)"는 의무가 아니게 되어 두지 않았다 — **검토 확인 필요** |
| 비회원 체험 기록 | **마지막 이용 후 30일** | 게스트 쿠키 수명이 30일이다. 쿠키가 사라지면 그 기록은 누구에게도 이어지지 않으므로 더 둘 이유가 없다. 그 전에 가입하면 회원 기록으로 옮겨진다(옮긴 경기는 회원 소유라 게스트 행을 지워도 남는다) |
| 로그인 기록 | **90일** | 계정 도용·이상 접속을 사후에 확인할 최소 기간. 통신 관련 법령의 접속 기록 보관 기간과 맞췄다 — **근거 조항은 검토에서 확정** |
| 쓰지 않는 로그인 세션 | **마지막 갱신 후 90일** | 위와 같은 기간. 90일 넘게 쓰지 않은 기기는 다시 로그인하게 된다 |
| 레이트 리밋 카운터 | **1시간** | 1분 단위 차단에만 쓴다. 이미 요청 중에 확률적으로 지우고 있었고, 파기 작업이 이를 보장한다 |
| 서버 오류 기록 | 〔배포 환경 확정 후〕 | 호스팅에 따라 보관 주체·기간이 다르다. 30일을 권한다 |

### 2.1 판단의 원칙

- **지킬 수 없는 기간은 쓰지 않는다.** 처리방침에 숫자를 쓰기 전에 그 숫자대로 지우는
  코드를 먼저 만들었다. 이전에는 탈퇴 말고 지우는 경로가 없어서, 어떤 기간을 적어도 거짓이었다
- **짧게.** 보관할 이유를 댈 수 없는 기간은 두지 않는다
- **숫자는 한 곳에서.** 처리방침 화면은 `retention.ts`의 값을 그대로 그린다. DB 함수의 기본
  인자와 어긋나면 통합 테스트가 실패한다

### 2.2 무엇이 지워지는가 (0016)

```
비회원:  guest_sessions 중 max(발급, 체험 일자, 마지막 경기) < now() - 30일
         → 그 게스트의 play_sessions·at_bats CASCADE
로그인:  auth.audit_log_entries.created_at < now() - 90일
세션:    auth.sessions 의 마지막 갱신 < now() - 90일 → refresh_tokens CASCADE
레이트:  rate_limit_counters.window_start < now() - 1시간
```

### 2.3 언제 지워지는가

1. **원칙**: 운영자가 하루 한 번 `npm run privacy:purge`(크론)
2. **안전망**: 경기를 시작할 때 마지막 실행이 하루를 넘었으면 응답 뒤에 한 번 돈다
   (`src/server/privacy/purge.ts`). 여러 서버가 동시에 돌리지 않도록 `maintenance_runs`의
   조건부 갱신을 통과한 한 곳만 실행한다. 방문이 없는 날은 돌지 않는다 — 그래서 크론이 원칙이다

## 3. 만 14세 미만

법정대리인 동의 절차가 없으므로 **가입을 받지 않는다**(06 문서 §12-8을 이렇게 정했다).

- **언제 묻나**: 첫 로그인 직후(`/auth/callback` → `/welcome/age`). 비회원 기록 승계를 이
  확인 **뒤로** 미뤘다 — 확인 전에는 어떤 기록도 계정에 붙지 않는다
- **무엇을 남기나**: 확인한 시각만(`profiles.age_confirmed_at`). 생년월일은 묻지 않는다 —
  필요한 것은 "14세 이상인가"뿐이고, 생년월일은 더 많은 개인정보다
- **미만이라고 답하면**: 한 번 더 묻고 계정을 즉시 삭제한다. 비회원 기록은 비회원으로 남아
  30일 규칙을 따른다
- **건너뛰면**: 서버가 막는다. 확인 전 회원은 공식 경기 시작(`startSession`)과 승계 API가
  `AGE_CONFIRMATION_REQUIRED`(403)로 거절된다. `/play`는 확인 화면으로 보낸다
- **기존 회원**: 확인 시각이 비어 있으므로 다음에 경기를 시작할 때 한 번 묻는다

한계: 자기 신고다. 거짓으로 답하는 것은 막지 못한다. 연령 확인 수준을 높일지는 검토 항목이다.

## 4. 처리방침 초안의 구성

`/privacy`에 14개 항목: 처리 목적 · 항목 · 보유 기간과 파기 · 공개되는 정보(랭킹·공유 링크) ·
제3자 제공(없음) · 처리 위탁 · 국외 이전 · 이용자 권리 · 만 14세 미만 · 쿠키 · 안전성 확보
조치 · 보호책임자 · 권익 침해 구제 · 방침 변경.

이용자 권리는 **실제로 있는 기능**만 적었다: 내 데이터 내보내기(열람), 닉네임·대표 구단
변경(정정), 계정 삭제(삭제).

- [ ] 서버 오류 기록 보관 기간
- [ ] 안전성 확보 조치의 배포 후 항목(HTTPS, 접근 권한 관리 절차)
- [ ] 시행일 — 채우면 `PRIVACY_DRAFT = false`, `PRIVACY_EFFECTIVE_DATE` 설정

**법률 검토에서 확인할 것**
- [ ] 회원 기록 "탈퇴 시까지"가 충분한지(장기 미이용자 처리 방침을 따로 둘지)

- [ ] 랭킹·공유 링크로 닉네임·성적이 공개되는 점의 고지 방식(동의를 따로 받을지)
