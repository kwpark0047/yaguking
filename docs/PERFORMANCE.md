# 야구왕(YaguKing) 성능 가이드

## 현재 성능 지표

| 시나리오 | 연결 풀 5 | 연결 풀 10 (개선 후) | 목표 |
|----------|-----------|----------------------|------|
| 50명 동시 | p95 335ms ❌ | p95 ~250ms ✅ | 300ms |
| 100명 동시 | p95 439ms ❌ | 미측정 | 300ms |

## 성능 병목 분석

### 1. 연결 풀 크기 (해결됨)

기본값 5에서 10으로 상향. 50명 동시 접속 시 p95 335ms → ~250ms로 개선.

추가 튜닝 필요 시: `DATABASE_POOL_MAX` 환경변수로 조정.

### 2. XP 지급 N+1 쿼리 (해결됨)

기존: 정답 한 건당 `grantXp()` 호출 (SELECT + INSERT)
개선: `grantXpBatch()`로 한 번에 INSERT

예: 타석 10개 정답 시
- 기존: 20개 쿼리 (정답 10개 + 고급 보너스 10개)
- 개선: 2개 쿼리 (배치 INSERT × 2 사유)

### 3. 레이트 리밋 cleanup (해결됨)

기존: 요청당 2% 확률로 cleanup 실행 (예측 불가)
개선: 1분 간격 시간 기반 cleanup으로 변경

### 4. 질의 선택 쿼리

`pickQuestionId()`는 `order by random()` 사용. 문항 수천 단위에서는 충분하나, 규모가 커지면 샘플링 전략 변경 필요.

### 5. zone cells 개별 INSERT (미해결)

`finishSession`에서 존 히트맵 셀을 개별 INSERT (최대 ~20건). 배치 처리 적용 검토 필요.

## 성능 측정 방법

```bash
# 로드 스모크 테스트 실행
npm run load:smoke
```

측정 시 확인할 지표:
- 평균 응답 시간
- p95 응답 시간
- 최대 동시 연결 수
- DB 연결 풀 사용률
- 느린 쿼리 (pg_stat_activity)
