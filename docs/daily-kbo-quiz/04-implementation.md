## 2. 설계에서 바뀐 점

1. 집계는 `adminDaily`가 아니라 `kboSets/{날}/stats/summary`에 둔다. 하루 요약 작업이 그 문서를 통째로 다시 쓰기 때문이다.
2. 실행 기록은 `adminConfig/kboRuns`, 문제 수는 `adminConfig/kboQuiz`.
3. 관리자 화면에서 **경기 결과 입력은 받지 않는다**(사람 입력은 법무 확인 뒤). 돌아보기 문항만 출처와 함께 직접 쓴다.
4. 시작 기록(`guest_quiz_start`)은 첫 답으로 센다. 홈 카드 노출은 세지 않는다.
5. 난이도: 5문제 2·2·1, 10문제 5·3·2(남는 자리는 어려운 쪽).
6. 홈 카드 문구 "~은/는"을 날짜에 맞게 고쳤다.

## 4. 남은 문제

- **실제 경기 데이터 없음.** 이용 허락(문의서 발송)이 먼저다. 그때까지 경기 퀴즈는 테스트 데이터로만 돈다.
- **시작일 `KBO_QUIZ_START` = 2026-11-20(임시).** 처리방침 7일 전 공지를 지키려면 11-13까지 배포해야 한다. 늦어지면 이 값을 미룬다(`src/lib/kbo/set.ts`, 처리방침이 따라간다).
- **첫 화면에 쓸 "2026 시즌 돌아보기" 문항이 아직 없다.** 한국시리즈 결과를 공개 보도 두 곳 이상으로 대조해 관리자 화면에서 써야 한다(운영자 작업). 묶음이 없으면 홈 카드가 보이지 않고 화면은 "준비 중"이다.
- 돌아보기 제목이 "2026 시즌"으로 고정이다. 2027 시즌 전에 바꾼다.
- 익명 계정을 여러 개 만들면 정답을 미리 볼 수 있다. 공식 점수가 없어 받아들였다.
- 관리자 "수동 새로고침"은 없다. 자동 수집이 생기면 작업 큐로 더한다.
- 하루 완주 1,000명이면 무료 한도의 읽기 약 24%, 쓰기 약 35%(추정). 실제 사용량은 배포 뒤 확인.
