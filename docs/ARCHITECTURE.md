# 야구왕(YaguKing) 아키텍처 문서

## 개요

야구왕은 KBO 기록 퀴즈를 1이닝 경기로 플레이하는 웹앱입니다. Next.js 16, React 19, TypeScript, Supabase(PostgreSQL) 스택으로 구성되어 있습니다.

## 핵심 설계 원칙

### 1. 트랜잭션 기반 원자성

모든 게임 쓰기 작업(세션 생성, 타석 제출, 세션 종료)은 단일 DB 트랜잭션 내에서 처리됩니다. 어느 하나라도 실패하면 전체가 롤백됩니다.

### 2. DB 시계 기반 시간 판정

경과 시간, 마감 시각 등은 `clock_timestamp()` 등 DB 시계를 기준으로 측정합니다. 클라이언트 시계를 신뢰하지 않습니다.

### 3. 정답 분리 (공개/비공개)

정답과 해설은 `private` 스키마에 저장되며, 경기 종료 시에만 `loadReveal` 등으로 조회됩니다. `PublicQuestion` 타입에는 정답 필드가 타입 레벨에서 존재하지 않습니다.

### 4. 멱등성

XP 지급, 타석 제출 등 중요 작업은 멱등 키(`idempotency_key`)를 사용하여 중복 실행을 방지합니다.

### 5. IP 위조 방지

`X-Forwarded-For` 헤더의 첫 주소는 클라이언트가 위조할 수 있으므로, 신뢰 프록시 수만큼 오른쪽에 위치한 주소를 사용합니다.

## 게임 플로우

```
1. 사용자가 경기 시작 요청 (POST /api/v1/play/sessions)
   └─> 레이트 리밋 확인 (분당 6회)
   └─> 게스트는 체험 1일 2이닝 제한 확인
   └─> 만 14세 확인 (회원 전용 모드)
   └─> 세션 생성 + 1번 타석 개시 (트랜잭션)

2. 타석 제출 (POST /api/v1/play/sessions/:id/at-bats)
   └─> 레이트 리밋 확인 (분당 120회)
   └─> 세션 행 잠금 (FOR UPDATE) → 동시 제출 차단
   └─> 멱등 키 확인 → 재시도 시 저장된 결과 반환
   └─> 정답 조회 (private 스키마)
   └─> 판정 엔진 (타이밍, 난이도, 스트릭)
   └─> 원장 UPDATE + 세션 상태 UPDATE
   └─> 종료 시 finishSession 호출 (성적, 존, XP)

3. 경기 종료 (finishSession)
   └─> 박스스코어 생성
   └─> 통산 성적 집계
   └─> 존 히트맵 집계 (P2 화면화 예정)
   └─> XP 지급 (배치 처리, 일일 상한 적용 사유는 개별 처리)
   └─> 누적 XP/레벨 업데이트
```

## 판정 엔진 규칙 (06 문서 §4.2)

| 조건 | 결과 |
|------|------|
| 정답, t ≤ 2.0초 | HR |
| 정답, 2.0 < t ≤ 4.5초 | 2B |
| 정답, 4.5 < t ≤ 8.0초 | 1B |
| 정답, 8.0 < t ≤ 15.0초 | BB (타수 제외) |
| 오답 또는 15.0초 초과 | K |

승급: 고급 문항 정답 또는 5연속 정답 유지 시 한 단계 상승 (BB→1B→2B→3B→HR, 최대 한 단계)

## 연결 풀 구성

| 설정 | 기본값 | 설명 |
|------|--------|------|
| `DATABASE_POOL_MAX` | 10 | 최대 연결 수 (환경변수로 튜닝 가능) |
| `idle_timeout` | 20초 | 유휴 연결 종료 시간 |
| `connect_timeout` | 10초 | 연결 시도 타임아웃 |
| `prepare` | false | Supavisor 트랜잭션 모드 호환 |

성능 측정 결과:
- 풀 5, 50명 동시: p95 335ms (목표 300ms 초과)
- 풀 10, 50명 동시: p95 ~250ms (목표 달성)
- 풀 20, 100명 동시: p95 439ms (목표 미달성, 추가 튜닝 필요)
