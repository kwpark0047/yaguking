# 야구왕 — Firebase 무료(Spark) 판

기존 Next.js + Supabase 앱(`..`)을 **Firebase Spark 무료 플랜만으로** 다시 만드는 폴더다.
Supabase·Vercel·Cloud Functions·유료 API를 쓰지 않는다. 전환의 배경과 기존 문서별로 바뀐 점은 16 문서
(`../KBO_YaguKing_Docs_20261023/16_야구왕_무료플랜_Firebase_전환.md`), 검증 결과는 `docs/verification-report.md`.

## 무료 플랜이라서 생기는 원칙

- **서버 코드가 없다.** Firestore 보안 규칙(`firestore.rules`)이 유일한 서버 쪽 방어선이다
- 기기에서 계산한 점수는 조작할 수 있으므로 **공식 랭킹·공식 XP에 넣지 않는다**(공식 기능은 별도 단계)
- 하루 한도(읽기 5만·쓰기 2만, Hosting 전송 360 MB)를 넘지 않게 읽기·구독·화면 크기를 줄인다
- 이메일 링크 로그인은 하루 5통이라 쓰지 않는다(이메일·비밀번호, 구글, 익명 로그인)

## 실행

```bash
npm install
npm run dev          # http://localhost:5173 (기본: 로컬 에뮬레이터 모드)
npm test             # 단위 테스트
npm run build        # 정적 사이트 → dist/
npm run emulators    # Auth·Firestore·Hosting 에뮬레이터 (JDK 21 필요)
npm run emulators:auth  # Auth 에뮬레이터만 (Java 없이 돈다)
npm run test:e2e     # Playwright — Auth 에뮬레이터와 개발 서버를 스스로 띄운다
npm run test:rules   # Firestore 보안 규칙 테스트 (JDK 21 필요)
npm run content:build  # 문제은행 CSV(../data) → src/content/questions.generated.json
npm run test:ops     # 정리 작업 테스트 (Auth·Firestore 에뮬레이터)
npm run deploy:check # 배포 전 점검만(운영 빌드 + 결과물 검사, 배포 안 함) — docs/deploy.md
```

프로젝트 ID는 `demo-yaguking`이다. `demo-`로 시작하는 ID는 에뮬레이터 전용이라 실제 Firebase에
닿지 않는다. 실제 프로젝트를 만들면 `.env.example`을 `.env.local`로 복사해 값을 넣는다.
**실제 배포(`firebase deploy`)는 사용자 승인 후에만 한다.**

## 1단계 — 로그인 (2026-10-26)

- **이메일·비밀번호 / 구글 / 익명(비회원)**. 이메일 링크 로그인은 Spark에서 하루 5통이라 쓰지 않는다
- **비회원 → 가입은 계정 연결**(`linkWithCredential`·`linkWithPopup`): uid가 그대로라 비회원 기록이
  자동으로 회원 기록이 된다. 기존 앱의 서버 "기록 승계"를 대신한다. 비회원이 **기존 계정으로 로그인**하면
  그 계정으로 바뀌므로 비회원 기록은 따라가지 않는다 — 화면이 미리 알린다
- **만 14세 확인**: 회원은 `users/{uid}`(확인 시각=서버 시각)를 만들 때까지 `/welcome/age`에 머문다.
  화면은 안내일 뿐이고 **막는 것은 `firestore.rules`**(`ageConfirmed()` — 2단계부터 모든 회원 기록 규칙이 요구)
- 미만이라고 답하면 기록과 계정을 지운다. 비회원에서 가입한 계정이면 그 비회원 기록도 함께 지워진다
  (**9단계에서 고침** — 그전에는 프로필 문서와 계정만 지워 비회원 기록이 남았다)
- 비밀번호 재설정 메일(하루 150통). 없는 이메일이어도 같은 안내 — 가입 여부를 캐낼 수 없게
- 로그인 실패 문구는 "없는 계정"과 "틀린 비밀번호"를 구분하지 않는다
- 제목 글꼴 Jua는 `@fontsource/jua`로 자체 호스팅(구글 글꼴 서버에 요청하지 않음)

**검증** (JDK 21 설치 후, 2026-10-26): 단위 500개, **보안 규칙 9개**(Firestore 에뮬레이터 — 서버 시각 조건을
지우면 실패하는 것도 확인), **E2E 30개**(Auth + Firestore 에뮬레이터, 360·1280 — 가입·로그인·로그아웃·구글·
비회원 연결·오류 문구·접근성, 만 14세 확인 저장·재확인 없음·비회원 가입 후 확인·미만 응답 시 계정 삭제).

Java는 `C:\Program Files\Eclipse Adoptium\jdk-21…`에 설치돼 있다. 설치 전에 열린 터미널은 PATH를 모르므로
새 터미널을 연다. E2E는 Java가 있으면 Firestore 에뮬레이터까지 스스로 띄운다.

## 2단계 — 데이터 구조와 보안 규칙 (2026-10-26)

`docs/data-model.md`에 정리했다. 요점:

- **문항은 Firestore에 없다.** 정적 JSON(압축 42 KB)으로 앱에 들어가 문항 읽기 비용이 0이다.
  정답이 기기로 내려가므로 경기는 비공식이다. 보기 섞기를 기존 앱과 같게 해 정답 위치 분포가 같다
- 컬렉션: 프로필, 닉네임 예약(대소문자 무시 유일), 경기 기록(끝날 때 1번), 비회원 하루 카운터,
  누적 기록, 오답노트, 친구 대결 방·자리
- 규칙이 지키는 것: 주인, 서버 시각, 필드 목록, 범위, 비회원 하루 3경기(KST), 닉네임 유일,
  레벨 테스트 1회, 방 정원·방장 권한·답 한 개씩
- **검증**: 규칙 테스트 44개(에뮬레이터, 파일별로 프로젝트를 나눠 서로 데이터를 지우지 않게),
  핵심 규칙 3개(비회원 제한·명단 없는 자리·닉네임 예약)를 지우면 테스트가 실패하는 것 확인.
  단위 508개(문제은행 분포·문서 ID 계산이 규칙과 같은지 포함)
- 고친 것: 규칙의 날짜 계산이 소수(`"20387.0"`)가 되어 비회원 카운터 문서 ID와 어긋났다 → `int()`

## 3단계 — 프로필 (2026-10-26)

- **가입 흐름**: 로그인 → 만 14세 확인 → 프로필 설정(`/welcome/profile`) → 메인. 닉네임과 최애 구단
  1위가 없으면 메인 대신 프로필 설정으로 보낸다(화면 안내, 실제 강제는 규칙)
  1. 닉네임 — 추천값이 미리 채워져 있다. 다음을 누를 때 다른 선수가 쓰는지 확인(읽기 1번)
  2. 최애 구단 TOP3 — **누른 순서가 순위**, 다시 누르면 빠진다. 1위는 필수. 고르는 순간 화면 전체가
     1위 구단 테마로 바뀐다(구단 로고 없음, 색은 보조, 순위는 글자로도)
  3. 최애 선수 — 자유 입력 0~3명(선택). 선수 명단 DB를 두지 않는다
- 저장은 **한 묶음**: 프로필 + 닉네임 예약(새 것 잡기·옛 것 놓기). 대소문자만 바뀌면 예약은 그대로
- **설정**(`/settings`): 닉네임·구단·선수 바꾸기, 로그아웃, **계정 삭제**(닉네임 입력해야 열림).
  삭제는 경기 기록·오답노트·누적·카운터·닉네임 예약·프로필을 지우고 계정을 지운다. Firebase가 최근
  로그인을 요구하므로 **지우기 전에** 확인한다 — 기록만 지워지고 계정이 남는 일을 막는다
- 프로필을 못 읽으면 설정은 빈 양식 대신 "다시 불러오기"를 보인다(빈 양식으로 덮어쓰지 않게)

**검증**: 단위 517, 규칙 44, E2E 40(가입 흐름 전체·닉네임 중복(대소문자 무시)·설정 변경 시 옛 닉네임
해제·구단 테마 적용·계정 삭제 후 계정/프로필/예약 모두 없음·접근성).

## 4단계 — 레벨 테스트, 개인 퀴즈, 오답노트 (2026-10-26)

- **개인 퀴즈**(`/play`): 메인의 "게임 시작" 한 번이면 첫 문제가 뜬다. 로그인하지 않았으면 그 자리에서
  비회원(익명)으로 들어간다 — 메인의 "비회원으로 시작" 버튼은 없앴다. 1이닝(3아웃), 문제당 15초,
  빨리 맞힐수록 큰 타구(기존 엔진 `resolveAtBat` 그대로). 1·2번 타석은 쉬움·보통, 그 뒤는 섞는다.
  최근 본 150문항은 기기에 기억해 되도록 다시 내지 않는다
- 판정 화면: 타구·정답·해설·출처. 경기가 끝나면 박스스코어와 **비공식 XP**(정답 10, 어려움 +5,
  이닝 완료 20). 저장은 **경기 끝날 때 한 묶음**(경기·누적·비회원 카운터·오답) — 실패하면 다시 저장 버튼
- **비회원 하루 3판**(KST, `src/lib/game/guestLimit.ts` 한 곳): 화면이 남은 판을 보여 주고, 4번째는 가입 안내. 실제로 막는 것은 규칙
- **레벨 테스트**(`/level-test`, 회원 1회): 20문항 — 규칙·상식 8, 한국시리즈 4, 선수 기록 4, 구단 역사 4
  (문제은행에 "역사" 영역 문항이 없어 4개 영역으로 냈다). **맞힌 수**로 처음 등급 Lv.1~5(PRD: 0~5·6~9·10~13·14~17·18~20 —
  7단계 뒤 PRD에 맞춰 고침). 규칙이 한 번만 받고, 등급이 맞힌 수 구간과 맞는지도 검사한다
- **오답노트**(`/notes`): 틀린 문항이 1·3·7·14일 뒤에 다시 나온다. 다시 틀리면 처음부터,
  14일 복습까지 맞히면 "익힌 문제". 화면을 열 때 최대 100개를 한 번 읽는다
- 비용은 `docs/data-model.md` §3 — 판당 읽기 약 2~8, 쓰기 약 2~6

**검증**: 단위 530(타석 계획·문항 고르기·경기 진행·XP·레벨 테스트 영역 배분·등급·복습 간격),
규칙 44, E2E 52(360·1280 — 비회원 1이닝 후 경기·누적·카운터·오답 문서 확인, 하루 3판 제한,
판정 화면, 복습 시각이 지난 노트를 풀어 단계 상승, 레벨 테스트 19/20 → Lv.5·한 번만, 접근성).
E2E는 문제은행을 직접 읽어 화면의 문제를 일부러 맞히거나 틀린다.

## 5단계 — 비공식 친구 대결 (2026-10-26)

- **흐름**: 메인 "친구 대결"(`/room`) → 방 만들기(정원 2·3·4·6·10명, 기본 4 / 문제 5·10·15, 기본 10)
  → 대기실에 6자 코드와 초대 링크(`/room/코드`) → 친구가 링크로 들어온다 → 방장이 시작(2명 이상)
  → 각자 풀기 → 최종 순위. 비회원도 된다 — 링크를 연 사람은 그 자리에서 비회원으로 들어가고 이름만 적는다
- **실시간 구독**은 방 문서와 자리 목록 두 개뿐이다. 모두 같은 문제를 **각자 속도로** 풀어서 방장이
  문제마다 넘기지 않는다 → 방 문서는 시작·종료 때만 바뀐다. 자리 구독은 방에 들어간 사람만 한다
- 점수: 정답 100점 + 빠를수록 최대 50점. 동점이면 맞힌 문제에 쓴 시간이 짧은 쪽이 위.
  기기가 채점한 **비공식** 점수라 랭킹·XP에 넣지 않고, 경기 기록(`games`)도 남기지 않는다.
  그래서 비회원 하루 3판 제한과도 따로 센다
- 다 같이 끝나면 방장 기기가 방을 끝낸다. 끝나지 않는 친구가 있으면 방장이 "지금 끝내기"
- 대기 중에 나가기(명단에서 자기만 빠짐 — **규칙 추가**), 방장은 방 닫기. 새로고침해도 자기 자리의
  답에서 이어 푼다. 답은 배열 전체를 쓴다(`arrayUnion`은 같은 답 두 개를 하나로 합쳐 규칙에 걸린다)
- 남는 것: 닫힌 방에 남은 다른 사람 자리, 끝난 방 — 자동 삭제(TTL)가 유료라 8단계 정리 스크립트가 지운다
- 비용은 `docs/data-model.md` §3 — 4명·10문제 한 판에 읽기 약 200, 쓰기 약 40

**검증**: 단위 540(점수·순위·동점·출제 비율·방 코드·이름), 규칙 45(나가기: 남을 빼기·방장·시작 후
거절), E2E 60(360·1280 — **브라우저 두 개로** 링크 참가 → 대기실 실시간 반영 → 시작 신호 → 각자 풀기 →
양쪽 최종 순위·방 상태 finished, 정원 초과·나가기 후 재참가·방장 닫기, 잘못된·없는 코드, 접근성).

## 6단계 — 무료 할당량 최적화 (2026-10-26)

`docs/usage-report.md`에 측정 방법·결과·하루 수용 인원을 정리했다. 요점:

- **경기 저장은 읽지 않는다**: 누적·비회원 카운터·오답 횟수를 서버 증가 연산(`increment`)으로 올린다.
  규칙은 증가가 끝난 값을 검사하므로 비회원 하루 3판·경기 수 +1 같은 조건은 그대로 지켜진다(규칙 테스트로 확인).
  회원 한 판 읽기 4 → **0**, 비회원 6 → **1**, 레벨 테스트 최대 21 → **1**
- **오답노트는 30개씩**(복습 시각 순, "더 보기"). 익힌 문항은 맨 뒤로 민다. "처음 틀린 시각" 필드는 없앴다
- **제목 글꼴을 줄였다**: 화면 문구에 쓰인 한글 590자만 남긴 Jua(360 KB → 125 KB, `npm run font:subset` —
  빌드가 다시 만들고, 단위 테스트가 문구와 어긋나지 않았는지 본다). 첫 방문 694 KB → **459 KB**
- **하루 한도를 넘으면** 화면이 "오늘 무료 사용량이 다 찼어요(한국 오후 4~5시쯤 다시)"라고 알린다
- **측정 도구**: 앱 안 계량기 + `npm run usage:measure`(예산 넘으면 실패하는 E2E) +
  `npm run usage:transfer`(Hosting 첫 방문 전송량)
- 하루 수용(추정): 쓰기가 먼저 찬다 — 회원만 약 1,100명, 비회원만 약 1,100명(하루 3판). Hosting 첫 방문 약 800명

**검증**: 단위 547(글꼴 문구 누락·한도 문구·계량기·노트 쪽 크기), 규칙 49(증가 연산으로 저장해도 하루 3판·
경기 수 +1·안타≤타수가 지켜짐, 없앤 필드 거절), E2E 68(360·1280 — 사용량 예산 3개, 오답노트 35개 → 30 + 더 보기),
빌드. 화면 확인: 메인 제목이 줄인 글꼴로 그려짐(`document.fonts`), 제목 줄바꿈을 단어 단위로.

## 7단계 — 공식 XP·RP 분리 설계 (2026-10-26, 설계만)

`docs/official-xp-rp.md`. **앱 코드·배포 규칙·워크플로는 바꾸지 않았다.** 요점:

  실패하는 것까지. 배포 규칙에서 공식 경로가 지금 모두 막혀 있는지도 테스트로 확인(규칙 테스트 56개)

## 8단계 — Hosting 배포 설정, GitHub 자동 배포(꺼진 상태) (2026-10-26)

**배포는 하지 않았다.** 실제 프로젝트·원격 저장소가 없고, 실제 배포는 사용자 승인 뒤에 한다. 사용자가 할 일은 `docs/deploy.md`.

- **Hosting 설정**(`firebase.json`): 화면은 `no-cache`(새 배포가 바로 보임), 해시 이름 파일은 1년 캐시. 보안 헤더(클릭재킹 막기,
  권한 정책, 팝업 로그인을 위한 COOP), CSP는 먼저 **보고 전용**으로(미리보기에서 위반이 없으면 강제로), 출시 전까지 `noindex`.
  소스맵은 올리지 않는다. 같은 헤더는 뒤 규칙이 이기므로 전체(`**`)를 먼저, `/assets/**`를 뒤에(로컬 Hosting 에뮬레이터는
  사용자 헤더를 붙이지 않아 미리보기에서 `curl -I`로 확인)
- **배포 직전 자동 점검**(`scripts/predeploy-check.mjs`, `firebase.json` predeploy): `demo-` 프로젝트·빈 설정·다른 프로젝트 설정을
  거절하고, 운영용으로 다시 빌드한 뒤 에뮬레이터 주소·데모 설정·개인 키·서비스 계정·소스맵·공식 정답이 섞였으면 배포를 멈춘다
- **정리 작업**(`ops/cleanup.mjs`): 24시간 지난 대결 방과 자리, 주인 없는 자리, 30일 쓰지 않은 비회원 계정·기록(기존 처리방침
  기준). 기본은 미리 보기, 한 번에 최대 5,000문서(무료 삭제 한도), 기록을 지운 뒤 계정을 지운다. 회원은 건드리지 않는다
- **GitHub**(저장소 루트 `.github/workflows/`): `firebase-app-ci.yml`은 검사만(타입·단위·빌드·규칙·정리·E2E).
  `firebase-deploy.yml`·`firebase-cleanup.yml`은 **꺼짐** — 손으로만 돌고, 저장소 변수(`FIREBASE_DEPLOY_ENABLED`·
  `FIREBASE_CLEANUP_ENABLED`)가 없으면 건너뛰며, 실제 배포는 production 환경 승인을 거친다. 인증은 키 파일 없는 WIF
- 의존성: `firebase-admin`(정리 작업용, 앱 묶음에 안 들어감), `cross-env`를 개발 의존성으로 고정

**검증**: 단위 559(배포 점검 — 데모·빈 설정·다른 프로젝트 거절, 에뮬레이터 빌드·비밀·소스맵 거절, Hosting 헤더 순서,
**배포·정리 워크플로가 꺼져 있는지**), 정리 작업 7(에뮬레이터에서 실제로 지움: 미리 보기는 안 지움, 24시간 방·주인 없는 자리,
30일 비회원 계정·기록 삭제와 회원 보존, 상한에서 멈춤), 규칙 59, E2E 68, 빌드. 점검 스크립트를 실제로 돌려 데모 프로젝트는
거절, 운영 빌드는 통과, 에뮬레이터 빌드는 거절되는 것을 확인. 정리 CLI는 에뮬레이터에서 실제 프로젝트 ID를 거절.

## 관리자 1차 — 골격·공지·가입자·가입 확인 (2026-10-27, 로컬 검증까지·배포 전)

기획 `docs/admin-plan.md`, 결정: 별도 관리자 사이트, 가입 확인은 점검 목록, 자체 광고만, 무료 꾸미기 아이템.

- **관리자 사이트**(`admin/` → `dist-admin/`, 두 번째 Hosting 사이트 `yaguking-bc25c-admin`): `npm run admin:dev`(5175).

- **대시보드**: 회원·오늘 가입·오늘 경기(경기 묶음 `count()`)·비회원(동기화 기준)·대결 방·처리 대기 작업, 계정 동기화 요청
