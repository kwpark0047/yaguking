## 0. 왜 재미가 없나(진단)

| 원인 | 근거 |
|---|---|
| 문제가 한 가지 모양 | 모든 타석이 "4지선다 + 15초". 손이 하는 일이 매번 같다 |
| 내용이 규칙 위주 | 문제은행 505문항 중 **규칙 432(86%)**, 그중 쉬운 규칙 200. 선수 기록 34, 한국시리즈 34, 구단 역사 5 |
| 지식만 겨룬다 | 몰라도 할 수 있는 순간(손맛·감·운)이 없다 — 야구는 "타이밍" 놀이인데 그게 빠져 있다 |
| 1이닝이 짧고 균일 | 6~9타석이 같은 리듬으로 흘러 기억에 남는 장면이 없다 |

## 1. 원칙

1. **3~5초, 한두 번 누르기.** 문제보다 쉽고 빠르게. 설명 없이 화면만 보고 바로 알 수 있게
2. **몰라도 할 수 있게.** 절반은 지식이 아니라 손맛(타이밍)·눈(판정)·감(어림)
3. **잘하면 보너스, 못해도 손해 없음.** 실패해도 아웃이 늘지 않는다(경기 흐름은 문제 타석이 정한다)
4. **콘텐츠 권리 걱정 없는 것부터.** 그때그때 만들어지는 놀이(스트라이크 존·타이밍)와 우리가 직접 쓴 짧은 문항(초성·O/X)만.
   실제 선수 사진·구단 로고·경기 영상은 쓰지 않는다
5. **무료 그대로.** 모두 기기 안에서 — 읽기·쓰기 늘지 않음(결과는 경기 끝 저장 묶음에 함께)
6. **비공식.** 보너스도 기기 계산 — 공식 랭킹과 무관

## 3. 언제 나오나

- 한 경기에 **최대 2번**. 아무 때나가 아니라 "찬스"로 의미가 있게:
  - **연속 정답 2개** 뒤 → "찬스! 보너스 타격"(A)
  - **2아웃** 되는 순간 → "마지막 찬스"(B 또는 C 중 무작위)
  - 위 조건이 안 생기면 4번째 타석 뒤에 한 번(B 또는 C)
- 이벤트 시작 전 0.8초 띠: "찬스 이벤트 — 타이밍 배팅!"(이미 있는 띠 부품). 건너뛰기 단추 항상
- 레벨 테스트에는 넣지 않는다(실력 측정 공정성). 친구 대결은 3차에 "모두 같은 이벤트"로 검토

## 4. 1차 상세

### A. 타이밍 배팅
- 화면: 홈플레이트와 스트라이크 존(SVG), 투수 쪽에서 공이 커지며 다가옴(0.9~1.4초, 무작위 속도·살짝 휘는 궤적)
- 누르기: 화면 아무 곳 탭 / 스페이스·엔터. 판정 창 — 퍼펙트 ±60ms, 굿 ±150ms, 그 밖 헛스윙
- 결과: 퍼펙트 → "홈런!" 폭죽(기존 효과) + 소리 "딱", 굿 → "안타!" 주자 진루, 헛스윙 → "아쉬워요" (아웃 아님)
- 동작 줄이기·화면 효과 끄기: 공이 움직이지 않고 **원이 줄어드는 타이밍 링**으로(움직임 최소) — 같은 판정
- 화면 읽기: "곧 공이 옵니다, 신호음이 나면 누르세요"가 맞지 않으므로 **건너뛰기를 기본 안내**하고, 대신 C를 내준다

### B. 스트라이크? 볼?
- 존 그림(9칸 + 바깥)과 공 자국 하나를 무작위로(경계 근처는 피해 판정이 모호하지 않게). "스트라이크" / "볼" 두 단추, 2초
- 3개 연속(한 번에 이어서 3구) — 다 맞히면 볼넷 효과, 하나라도 틀리면 그 자리에서 끝(아웃 아님)
- 판정 규칙은 단순화한 존(키 기준 고정 높이)으로 — "실제 심판 판정과 다를 수 있어요" 표시

### C. 초성 퀴즈
- "ㅎ ㄹ" + 힌트 한 줄("담장을 넘기면?") → 보기 3개(홈런·희생번트·홀드). 5초
- 용어 80개는 우리가 직접 쓴 짧은 설명(규칙서 문장을 옮기지 않음), 초성은 코드가 계산
- 정답 → 다음 문제 시간 +3초(15→18초) — 지식 보상이 다음 타석으로 이어진다

## 5. 경기 엔진·저장

- 엔진(`src/lib/engine`)은 그대로 두고, 이벤트 결과를 **경기 상태에 덧붙이는 함수** 하나: `applyBonus(state, bonus)` —
  홈런(+1점, 주자 모두 홈인), 진루, 볼넷, 시간 보너스. 단위 테스트로 주자·득점 계산 확인
- 저장: 경기 문서에 `events`(최대 2개: 종류·결과) 필드 추가 → 보안 규칙의 경기 필드 목록·모양 검사에 추가, 득점 상한(99)은 그대로.
  처리방침 "경기 기록" 항목 범위 안(새 개인정보 아님)
- XP: 이벤트 성공 소량(+10) — 비공식 XP 계산(`xpOf`)에 반영
- 관리자 "오늘 경기"·하루 요약에 이벤트 성공률을 더해 재미 지표로 본다(어떤 이벤트가 인기인지)

## 6. 내용 보강(재미의 다른 절반)

이벤트와 별개로 문제은행 쏠림(규칙 86%)을 줄인다 — 운영자가 문항을 더 써야 하는 일이라 따로 정한다:
- 한 경기 출제에서 **규칙 문항을 절반 이하로**(지금 출제는 난이도만 고른다 — 영역 비율을 더하면 된다) — 코드만으로 가능
- 재미 영역 문항 추가 후보(직접 작성, 출처 표기): 야구장 문화·응원·별명·용어 유래(권리 문제 적음). 실제 기록 문항은 데이터 권리 확보 뒤

## 7. 확인 방법

- 단위: 보너스 적용(주자·득점), 이벤트 등장 조건(연속 2·2아웃·4타석, 최대 2), 스트라이크 존 무작위 위치가 경계에서 떨어짐, 초성 계산
- E2E: 이벤트가 뜨고 건너뛸 수 있음, 성공·실패 후 경기 계속, 저장 묶음에 events, 동작 줄이기 대체 화면, axe
- 재미 확인: 운영자와 몇 사람이 직접 해 보고 "또 하고 싶은가" — 관리자 지표(이벤트 성공률·경기당 판 수 변화)

## 9. 정해 주실 것

1. 1차 이벤트 — **A 타이밍·B 스트라이크 판정·C 초성(권장)** / 다른 조합
2. 한 경기 횟수 — **최대 2번(권장)** / 1번 / 3번
3. 실패했을 때 — **손해 없음(권장)** / 아웃 1개(긴장감)
4. 출제에서 규칙 문항 비율 — **절반 이하로 줄이기(권장)** / 그대로
