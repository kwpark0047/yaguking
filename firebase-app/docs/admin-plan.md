## 2. 관리자 판별과 접근

| 단계 | 방법 |
|---|---|
| 표시 붙이기 | `ops/set-admin.mjs --email=kwpark0047@gmail.com`(운영자 PC, Admin SDK `setCustomUserClaims({admin:true})`) — 한 번. 떼기도 같은 스크립트 |
| 로그인 | 관리자 사이트는 **구글 로그인만**. 토큰에 `admin == true`이고 `email_verified == true`일 때만 화면을 연다 |
| 서버 쪽 막기 | 보안 규칙 `isAdmin() = request.auth.token.admin == true` — 관리자 컬렉션·다른 사람 기록 읽기/지우기는 이 조건 |
| 세션 | 30분 동안 아무것도 안 하면 로그아웃. 삭제·지급 같은 되돌릴 수 없는 일은 대상 이름을 다시 입력해야 실행 |
| 기록 | 관리자 행동은 전부 `adminLogs`에 남는다(누가·무엇을·대상·서버 시각). 기기는 만들기만, 고치기·지우기 불가 |

규칙 초안(요지):

```
function isAdmin() { return request.auth != null && request.auth.token.admin == true
                       && request.auth.token.email_verified == true; }

match /users/{uid} { allow get, list: if isSelf(uid) || isAdmin(); allow delete: if isSelf(uid) || isAdmin(); }
match /{path=**}/games/{id} { allow list: if isAdmin(); }        // 컬렉션 묶음 집계(통계)
match /adminLogs/{id} { allow create: if isAdmin() && request.resource.data.at == request.time
                                       && request.resource.data.by == request.auth.uid;
                        allow read: if isAdmin(); allow update, delete: if false; }
match /adminTasks/{id} { allow create, read: if isAdmin(); allow update, delete: if false; }  // 처리는 Admin SDK
match /notices/{id} { allow read: if true; allow write: if isAdmin(); }   // events·items·ads도 같은 틀
match /public/home { allow read: if true; allow write: if isAdmin(); }
```

## 5. 기능별 상세

### 5.1 대시보드
- 카드: 오늘 가입(회원 `users` `createdAt ≥ 오늘` `count()`), 오늘 경기(`games` 컬렉션 묶음 `count()`), 활동 비회원(동기화 사본),
  대결 방 수(`rooms` `count()`), 무료 한도 추정(스냅샷 + 오늘 집계로 계산 — 실제 사용량은 콘솔 링크), 처리 대기 작업·정리 작업 마지막 결과
- 차트: 최근 7·30일(스냅샷 문서 7~30개 읽기)
- 비용: 화면 한 번 열 때 읽기 약 40(집계 쿼리는 1,000건당 1읽기)

### 5.2 가입 확인 (점검 목록)
**가입을 관리자가 승인하는 방식은 권하지 않는다** — 즉시 플레이 원칙(06 문서)과 맞지 않고, 승인 전 상태의 기록 처리가
복잡해진다. 대신 "가입이 제대로 끝났나"를 보는 목록:
- 최근 가입(동기화 사본 + 프로필): 로그인 수단, 이메일 인증, **만 14세 확인 시각**, 프로필(닉네임·구단) 완료 여부
- 표시: "가입했지만 14세 확인 안 함", "확인했지만 프로필 미완료"(앱이 막아 둔 상태) — 오래 남으면 정리 대상 후보
- 오늘 같은 문제(가입 시도 실패)는 Auth에 흔적이 없어 여기 안 보인다 → 가입 화면 오류는 E2E·콘솔로 본다(이번에 고친 안내 문구)

### 5.3 가입자 관리
- 목록: 최근 가입 순 30명씩, 닉네임 앞글자 검색(`nicknames` 문서 ID 범위 쿼리), 구단 필터
- 상세: 프로필, 누적 성적(`summary/main`), 레벨 테스트, 오답 수(`count()`), 최근 경기 5개, 관리자 기록
- **이메일은 기본 가림**(`kw***@gmail.com`). "보기"를 누르면 보이고 `adminLogs`에 열람 기록 — 개인정보 접속기록(§8)
- 하지 않는 것: 기록·점수 수정(비공식이라도 관리자가 고치면 신뢰가 깨짐 — 필요하면 삭제만)

### 5.4 계정 삭제
1. 관리자가 상세 화면에서 "계정 삭제" → 닉네임을 다시 입력 → 사유 선택(본인 요청/약관 위반/만 14세 미만 의심/기타)
2. 화면이 **같은 묶음으로**: 기록(경기·오답·누적·카운터·레벨 테스트)·프로필·닉네임 예약 삭제 + `adminTasks`(deleteAuthUser) + `adminLogs`
3. PC 작업이 로그인 계정을 지우고 작업을 "완료"로(최대 하루, 급하면 운영자가 `npm run ops:admin-tasks`로 즉시)
- **본인 요청이 아닌 삭제는 이용약관 근거가 먼저** — 지금 약관이 "확정 전"이라 그 전에는 본인 요청·만 14세 미만만 처리
- 비회원 삭제도 같은 경로(기록 + 익명 계정)

### 5.5 게임 통계
- 매일 03:30 PC 작업이 전날 경기를 한 번 읽어(`games` 컬렉션 묶음, 전날 범위) 스냅샷 1개를 쓴다 — 관리 화면은 스냅샷만 읽음
- 항목: 경기 수(비회원/회원), 평균 득점, 타석당 정답률, 영역·난이도별 정답률(문항 품질 점검에 씀), 많이 틀린 문항 TOP 10,
  레벨 테스트 등급 분포, 대결 방 수·평균 인원, 오답노트 복습 수
- 비용: 하루 경기 1,000판이면 스냅샷 만들 때 읽기 1,000(하루 1번). 오늘 수치는 `count()`로 몇 읽기
- 모두 **비공식 기록 기준**이라는 표시

### 5.6 이벤트 생성
- 입력: 이름, 기간(KST), 대상(전체/회원), 배너 문구, 종류
  - **테마 주간**: 특정 영역 문항을 더 자주 출제(기기 쪽 출제 가중치 — 비공식)
  - **출석 도장**: 기간 중 N일 경기하면 꾸미기 아이템(기기 계산 — 비공식, 중복 지급은 문서 ID로 막음)
  - **안내 전용**: 배너만(예: 한국시리즈 퀴즈 주간)
- 상품·경품(실물·상품권)은 **넣지 않는다**(§8 — 배송지 등 개인정보 수집, 경품 고시)

### 5.7 아이템 생성
- 꾸미기 전용·무료: 결과 카드 테두리, 프로필 배지, 대결 방 이름표 색
- 이미지: Spark에는 Storage가 없어 **이미지를 앱과 함께 배포**(`public/items/…`)하고 관리자 화면에서는 그 경로를 고른다.
  새 이미지를 넣으려면 배포가 한 번 필요하다
- 지급: 관리자 지급(가입자 상세에서) 또는 이벤트 조건 달성. 보유 목록 `users/{uid}/inventory`
- **유료·확률형(뽑기) 없음** — 결제가 없고, 확률형은 게임산업법상 확률 공개 의무가 생긴다

### 5.8 광고 게시
- **자체 광고(하우스 배너)만**: 다른 기능 안내, 협찬사 문구(협찬은 계약 후) — 문구·링크·기간·위치(메인 하단/경기 결과 아래)
- 화면에 **"광고"** 표시, 링크는 새 창 + `rel="sponsored noopener"`, 같은 광고 하루 노출 제한은 기기에서(서버 기록 없음)
- 외부 광고 네트워크(AdSense 등)는 **쓰지 않는다**: 처리방침의 "광고·분석 도구 없음"과 CSP를 바꿔야 하고, 이용자(만 14세 이상
  청소년 포함) 맞춤 광고·쿠키 문제가 생긴다. 쓰려면 별도 결정·처리방침 개정(시행 7일 전 공지)
- 클릭 수 집계는 하지 않는다(쓰기 비용·추적 우려). 필요하면 링크에 캠페인 표시(utm)만

### 5.9 공지사항
- 작성(글자만, 링크 허용 목록), 예약 공개, 상단 고정, 숨김, 미리 보기
- 이용자 앱: 메인 상단 띠(고정 공지 1개) + `/notices` 목록(최근 20개, `public/home`에 요약, 본문은 열 때 1읽기)
- 처리방침·약관 변경 공지에 쓴다(시행 7일 전 알림 의무)

## 6. 작업 대기열과 PC 작업 (서버 대신)

| 작업 | 누가 만듦 | PC 작업이 하는 일 |
|---|---|---|
| `deleteAuthUser` | 관리자(계정 삭제) | 로그인 계정 삭제, 남은 기록 다시 확인 후 삭제, 결과 기록 |
| `syncAccounts` | 매일 자동 + 관리자 "지금 동기화" | 로그인 계정 목록 → `accountMirror` 갱신(바뀐 것만 쓰기) |
| `dailyStats` | 매일 자동 | 전날 스냅샷 |
| `setAdmin` | (화면에서 만들지 않음) | 관리자 표시는 PC에서 직접만 — 화면이 관리자를 늘릴 수 없게 |

- 이미 있는 예약 작업 "YaguKing cleanup"(매일 03:30)에 이어 붙인다: `ops/run-cleanup.cmd` → 정리 + 대기열 + 동기화 + 스냅샷
- PC가 꺼져 있으면 늦어진다 → 대시보드에 "마지막 처리 시각" 표시. 늦어지면 GitHub Actions로 옮기는 안(처리방침에 GitHub 추가)
- 다른 안(채택 안 함): 관리자 사이트에서 구글 로그인 때 클라우드 권한(`cloud-platform`)을 받아 브라우저가 직접 계정 API를 부르는 방법 —
  즉시 처리되지만 **프로젝트 전체 권한 토큰이 브라우저에 1시간 머문다**. 화면 하나의 실수(XSS)가 프로젝트 전체 사고가 될 수 있어 쓰지 않는다

## 7. 무료 한도 영향 (추정)

| 항목 | 하루 |
|---|---|
| 이용자 앱 `public/home` 읽기 | 앱 열기 수만큼(1,000명 → 1,000) |
| 관리자 화면 | 하루 10번 열면 약 400~800 |
| PC 작업(동기화·스냅샷) | 읽기: 전날 경기 수 + 바뀐 계정, 쓰기: 바뀐 계정 + 1 |

현재 수용 추정(회원 하루 약 1,100명, `docs/usage-report.md`)에서 크게 줄지 않는다(약 5% 이내).

## 8. 개인정보·법

- **접속기록**: 개인정보를 다루는 관리자 접속·열람·삭제 기록을 남기고 **1년 이상 보관**(안전성 확보조치 기준) → `adminLogs`는
  정리 작업이 지우지 않는다. 처리방침 "안전성 확보 조치"에 "관리자 접속기록 보관"을 넣는다
- 처리방침 개정이 필요한 것: 관리자 열람·접속기록(위), 아이템 보유 기록(새 처리 항목), 공지·이벤트 참여 기록(출석 도장).
  **시행 7일 전 공지**(5.9의 공지 기능으로)
- 계정 삭제(본인 요청 아닌 경우)·이용 제한은 **이용약관 근거**가 필요 → 약관 확정이 선행
- 광고: "광고" 표시(표시광고법 취지), 청소년 유해 광고 금지, 맞춤 광고 없음
- 아이템: 무료·꾸미기 전용, 확률형 없음 / 이벤트: 실물 경품 없음(경품 제공 시 배송 정보 수집·고지 필요)
- 관리자 계정 보호: 구글 계정 2단계 인증 켜기(운영자가 직접), 관리자 사이트 로그인 수단은 구글만

## 9. 만드는 순서(승인 뒤)

| 단계 | 내용 | 검증 |
|---|---|---|
| A | 관리자 표시 스크립트, 규칙(`isAdmin`·기록·대기열), 관리자 사이트 골격(구글 로그인·대시보드 빈 카드) | 규칙 테스트(관리자/일반/표시 없는 관리자 이메일), 관리자 사이트 E2E |
| B | 공지사항 + `public/home` + 이용자 앱 띠·목록 | 이용자 앱 읽기 1회 확인(계량기), 예약 공개 |
| C | 가입자 목록·상세·가입 확인, PC 작업 `syncAccounts` | 이메일 가림·열람 기록, 동기화 테스트(에뮬레이터) |
| D | 계정 삭제(대기열 + PC 처리) | 삭제 후 기록·계정·예약 0, 기록 남음, 본인 요청 사유만 허용(약관 전) |
| E | 통계 스냅샷 + 대시보드 차트 | 스냅샷 숫자 = 에뮬레이터 직접 계산 |
| F | 이벤트·아이템 | 출석 도장 중복 지급 막힘, 꾸미기 표시 |
| G | 자체 광고 | "광고" 표시·rel 속성·노출 위치, 접근성 |

각 단계는 지금처럼: 단위·규칙·E2E·사용량 예산 → 미리보기 → 승인 → 실제 사이트.

## 10. 위험

| 위험 | 대응 |
|---|---|
| 관리자 계정 탈취 = 모든 기록 노출 | 구글 2단계 인증, 관리자 표시는 PC에서만, 30분 자동 로그아웃, 열람 기록 |
| 규칙 실수로 관리자 권한이 일반 이용자에게 열림 | 규칙 테스트에 "관리자 아님" 경우를 기능마다, 변이 확인(검사 줄을 빼면 실패) |
| PC가 꺼져 삭제가 늦어짐 | 대시보드에 마지막 처리 시각, 법정 기한(삭제 요청은 지체 없이 — 보통 10일 안) 안에서 운영자 수동 실행 |
| 관리 화면이 무료 한도를 씀 | 스냅샷 위주, 목록 30개씩, 집계 쿼리 |

## 11. 정해 주셔야 할 것

1. **관리자 사이트 분리**: 권장 — 별도 Hosting 사이트(`yaguking-bc25c-admin.web.app`). 대안: 같은 사이트의 `/admin`
2. **"가입 확인"의 뜻**: 권장 — 점검 목록(승인 없음). 대안: 관리자 승인 전에는 회원 기능 제한
3. **광고**: 권장 — 자체 광고만. 대안: 외부 광고 네트워크(처리방침·CSP 개정, 별도 검토)
4. **아이템**: 권장 — 무료 꾸미기 전용. 유료·확률형은 결제·법 문제로 하지 않음
5. **계정 삭제 사유**: 이용약관 확정 전에는 본인 요청·만 14세 미만만 — 약관 문안을 먼저 정할지
6. **첫 범위**: 권장 — A(골격)+B(공지)+C(가입자·가입 확인)를 1차로, D~G는 다음
