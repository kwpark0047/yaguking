# 검증 보고서 — 야구왕 Firebase 무료판 (9단계, 2026-10-26)

> 범위: `firebase-app/` 개발 0~9단계. **배포 전 보고서다** — 모든 검증은 로컬 에뮬레이터에서 했고, 실제 Firebase
> 프로젝트·원격 저장소·실제 사용자는 없다. 실제 환경에서만 확인할 수 있는 것은 §6에 따로 적었다.

## 0. 결론

- **배포 준비는 됐다(사용자 승인 대기).** 타입 검사·단위·보안 규칙·정리 작업·E2E·사용량 예산·배포 전 점검이 모두 통과했다
- 지시한 제약 7가지는 모두 코드와 테스트로 확인했다(§3). 유료 서비스·Cloud Functions·결제 계정은 쓰지 않는다
- 모든 점수·XP·등급은 **비공식**이다. 공식 XP·랭킹은 설계만 있다(`docs/official-xp-rp.md`)
- 이번 단계에서 **버그 1개**(만 14세 미만 응답 시 비회원 기록이 남음)와 **테스트 경쟁 1개**를 찾아 고쳤다(§5)
- 출시 전에 사용자가 할 일: 처리방침 초안 확정, 정리 작업 켜기, 프로젝트 만들기·배포(§7)

## 3. 지시한 제약 — 증거

| 제약 | 증거 |
|---|---|
| Supabase·Vercel·유료 API·유료 호스팅을 쓰지 않는다 | `firebase-app/package.json` 의존성에 없음. 처리방침에도 없음(단위 테스트가 "Supabase·Vercel" 문구를 막음) |
| Blaze로 전환하지 않는다 | 결제 계정이 필요한 기능 없음: TTL 대신 정리 작업, Cloud Functions 대신 GitHub Actions(꺼짐), Storage 없음. 배포 안내 §1에 "결제 계정 연결 안 함" |
| Cloud Functions·결제 기능을 쓰지 않는다 | `firebase.json`에 functions·storage 항목 없음. 서버 쪽 방어는 보안 규칙 59개 테스트 |
| 실제 KBO 기록을 자동 수집하지 않는다 | 수집 코드 없음. 문제은행은 저장소의 CSV(`../data`)를 `npm run content:build`로 변환만 |
| 조작 가능한 점수는 공식 랭킹에 넣지 않는다 | 화면마다 "비공식" 표시. 공식 경로(`officialStats`·`officialResults`·`leaderboards`·`officialKeys`)는 배포 규칙에서 기기 쓰기 거절(규칙 테스트). 랭킹 화면 자체가 없음 |
| 기존 파일을 임의 삭제·덮어쓰지 않는다 | 새 폴더에서 개발. 기존 코드는 복사(`COPIED_FROM.md`). 기획 문서 01~12·15는 머리에 안내 한 줄만 덧붙임(본문 변경 0, 27줄 추가) |
| 실제 배포 전 사용자 승인 | 배포 0회. 배포 워크플로는 수동 + 저장소 변수 + production 승인(단위 테스트가 꺼짐 상태를 지킴). 배포 직전 자동 점검 |

## 5. 이번 단계에서 찾아 고친 것

| 무엇 | 어떻게 찾았나 | 고친 것 |
|---|---|---|
| **만 14세 미만이라고 답하면 비회원 시절 경기·오답 기록이 남았다** (1단계 README는 "함께 지워진다"고 적었지만 프로필 문서와 계정만 지웠다) | 처리방침 초안을 쓰며 삭제 경로를 코드로 대조 → 실패하는 E2E를 먼저 씀 | 계정 삭제(설정)와 같은 기록 삭제 함수를 쓰게 함(`deleteUserRecords`). E2E로 경기·누적·카운터·오답 0건 확인 |
| 사용량 E2E가 프로필을 읽기 **전에** 계량기를 읽을 수 있었다("회원 선수, 반가워요!"는 프로필 전에도 보임) | 최종 실행에서 "앱 열기 0읽기"로 실패 → 모듈 주소·행동별 값을 찍어 원인 확인 | 닉네임이 보일 때까지 기다리게 함. 실패를 냈던 코드 상태에서도 고친 테스트가 통과함을 확인 |
| 처리방침 문안 중 사실과 다른 두 곳 | 규칙·로그아웃 코드와 대조 | "방 코드를 아는 로그인 이용자는 참가하지 않아도 참가자 이름·답·점수를 볼 수 있다", "기기 데이터 저장소는 로그아웃해도 남는다"로 고침 |
| 처리방침 표가 좁은 화면에서 키보드로 넘길 수 없었다 | 기존 axe 검사(`/privacy`)가 잡음 | 표 영역이 초점을 받고 이름을 가짐 |

이전 단계에서 찾아 고친 것(각 단계 README): 규칙의 날짜 계산이 소수(`"20387.0"`)가 되던 것, 레벨 테스트 등급이 PRD와
달랐던 것(정답 비율 → 정답 수), 공식전 설계의 "기한 필드"는 기기가 만들 수 없던 것, 개발 모드에서 오답노트를 두 번 읽던 것,
계정 삭제 순서(기록만 지워지고 계정이 남는 위험) 등.

## 6. 검증하지 못한 것

| 무엇 | 이유 | 확인할 때 |
|---|---|---|
| 실제 Firebase에서의 동작 전부(로그인·규칙·사용량) | 실제 프로젝트 없음 — 에뮬레이터만 | 배포 안내 §3 미리보기 점검표 |
| 구글 로그인 실제 팝업 | 에뮬레이터의 가짜 구글 화면으로만 검증 | 미리보기 주소(승인된 도메인 추가 필요할 수 있음) |
| Hosting 헤더(캐시·보안·CSP) | 로컬 Hosting 에뮬레이터가 사용자 헤더를 붙이지 않음. "같은 헤더는 뒤 규칙이 이긴다"는 문서가 아닌 이슈 보고에 근거 | 미리보기에서 `curl -I`, 콘솔의 CSP 보고 |
| GitHub Actions(CI·배포·정리) 실제 실행, WIF 인증 | 원격 저장소·GCP 설정 없음. YAML은 파싱과 단위 테스트로만 확인 | 저장소를 만든 뒤 CI 첫 실행 |
| 실제 사용량·한도 초과 화면 | 에뮬레이터는 한도가 없음. 한도 문구는 단위 테스트로만 | 콘솔 › 사용량(주 1회 점검표) |
| Safari·Firefox·실제 휴대폰, 화면 읽기 프로그램 | Chromium만, 접근성은 axe 자동 검사만 | 출시 전 실기 점검 |
| 많은 동시 대결 방(부하) | 2~3명 방만 | 소규모 공개 때 관찰 |
| 처리방침·이용약관의 법률 적합성 | 법률 검토 영역 | 사용자 검토(처리방침은 초안 표시) |

## 7. 남은 위험과 출시 전 할 일

1. **처리방침 초안 확정** — 국외 이전(Google·GitHub) 고지 검토, 시행일. 이용약관 문안은 아직 없음(자리 표시)
2. **정리 작업 켜기** — 켜지 않으면 처리방침의 "비회원 30일·대결 방 24시간 삭제"가 사실이 아니다(`docs/deploy.md` §6)
3. **프로젝트 만들기·첫 배포**(서울 리전, Spark, 결제 계정 없음) — `docs/deploy.md` §1~3
4. 비회원 하루 3판은 익명 계정을 새로 만들면 우회된다 → App Check 도입 여부 결정
5. 기기 데이터 저장소가 로그아웃 뒤에도 남는다(공용 기기) — 로그아웃 때 지우는 기능은 후보로 남김
6. 공식 XP·RP: 저장소 공개 여부·공식전 형태 등 6가지 결정(`docs/official-xp-rp.md` §10)

## 8. 다시 돌리는 법

`firebase-app`에서(JDK 21 필요):

```bash
npm run typecheck && npm test && npm run test:rules && npm run test:ops && npm run test:e2e && npm run usage:measure && npm run build
```
