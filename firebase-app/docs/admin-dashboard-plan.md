# 관리자 대시보드 2차 — 회원·오늘 경기·대결 방 세부 관리 (기획만)

2026-10-28. 관리자 1차(`docs/admin-plan.md`)의 대시보드는 **숫자 카드**(회원·오늘 가입·오늘 경기·대결 방·대기 작업)뿐이다.
이 문서는 각 숫자를 눌러 **무엇이, 누가, 어떻게** 되어 있는지 보고 필요한 조치를 하는 화면을 정한다.
**아직 만들지 않았다** — 승인 뒤 §10 순서대로.

## 0. 요약

| 영역 | 지금(1차) | 2차에서 |
|---|---|---|
| 대시보드 | 숫자 5개 | 숫자를 누르면 세부 화면, 기간(오늘·어제·7일), 가입 단계 깔때기, 무료 사용량 추정 |
| 회원 확인 | 목록·상세(11-03부터), 가입 점검 목록 | 상태 필터(14세 미확인·프로필 미완료·레벨 테스트 안 함·오래 안 옴), 상세 타임라인, 정해진 조치만 |
| 오늘 경기 | 개수 하나 | 요약(평균 득점·정답률·홈런율·시간대), 최근 경기 목록·타석별 상세, 이상 징후, 문항 품질 |

| 먼저 고칠 것 | — | **로그인한 누구나 대결 방·자리 전체 목록을 읽을 수 있다** → 목록은 관리자만(§6) |

모두 관리자 기록(`adminLogs`, 2년), 회원 개인 정보 열람은 **2026-11-03(처리방침 개정 시행일)부터**, 모든 숫자는 한국 시간·비공식.

## 1. 대시보드 재구성

```text
┌ 기간: [오늘] [어제] [최근 7일]                       집계 15:20 · 계정 사본 03:30 ┐
│ 회원 5 (+1)   비회원 활동 24   경기 37   대결 방 2(진행 1)   대기 작업 0          │  ← 숫자 = 링크
├ 가입 단계 깔때기  가입 6 → 14세 확인 5 → 프로필 5 → 레벨 테스트 3 → 첫 경기 4       │
├ 오늘 경기 요약  평균 1.2점 · 정답률 61% · 홈런 9% · 시간대 막대(0~23시)            │
├ 살펴볼 것  ⚠ 진행 멈춘 방 1 · ⚠ 14세 확인 안 하고 3일 지난 가입 2 · 이상 징후 0      │
└ 무료 사용량 추정  읽기 3,100/50,000 · 쓰기 410/20,000 (계량 추정, 실제는 콘솔)      ┘
```

- **숫자를 누르면 세부 화면**: 회원 → §2 목록(오늘 가입 필터), 경기 → §3, 대결 방 → §4, 대기 작업 → 작업 목록
- **기간**: 오늘·어제·최근 7일. 어제·7일은 운영자 PC의 매일 스냅샷(`stats/daily/days/{yyyymmdd}`, 1차 기획 §5.5)을 읽어 싸게,
  오늘만 직접 센다
- **살펴볼 것**: 사람이 손봐야 할 수 있는 것만 모은 줄(0이면 숨김). 누르면 해당 필터가 걸린 목록으로
- **무료 사용량 추정**: 오늘 경기 수·가입 수·방 수로 계산한 추정치 + 콘솔 사용량 링크(Spark에는 사용량 API·예산 알림이 없음)
- 자동 새로고침 없음(읽기 절약). "다시 세기" 버튼과 집계 시각 표시

### 2-1. 목록

| 필터 | 데이터 | 비고 |
|---|---|---|

| 정렬 | 가입순·마지막 로그인순·경기 수순 | 경기 수는 `summary/main` |

상태 배지(한 사람에게 하나, 앞쪽이 우선):

| 배지 | 뜻 | 살펴볼 것 |
|---|---|---|
| 14세 미확인 | 가입했지만 `users/{uid}` 없음 | 3일 넘으면 "살펴볼 것" — 앱이 막아 둔 상태라 기록이 없다 |
| 프로필 미완료 | 확인했지만 닉네임 없음 | 가입 화면 문제 신호 |
| 레벨 테스트 안 함 | 프로필 있음, `levelTest` 없음 | 안내 문구 개선 근거(숫자만 봄) |
| 활동 중 | 7일 안에 로그인 | |
| 오래 안 옴 | 90일 넘게 로그인 없음 | 회원은 자동 삭제하지 않는다(처리방침). 표시만 |
| 이메일 미인증 | 이메일 가입·인증 안 함 | 비밀번호 재설정 메일이 못 갈 수 있음 |

- 한 번에 30명, "더 보기". 가입 단계 깔때기 숫자를 누르면 그 단계에서 멈춘 사람 목록
- **비회원은 개별 목록을 두지 않는다**: 개수·활동 수(7일)만. 문의가 오면 uid로만 조회(이용자가 설정 화면에서 uid를 알려 줄 수 있게 —
  2차 이용자 앱 작업)

### 2-2. 상세

```text
곰돌이 · kw***@gmail.com [이메일 보기]  구글 · 인증됨 · 가입 10-27 12:51 · 마지막 로그인 10-28 15:01
타임라인  가입 → 14세 확인(12:52) → 프로필(12:53) → 레벨 테스트 Lv.4(13:10) → 경기 12판 · 대결 2번
누적(비공식)  12경기 · 타율 .312 · 홈런 4 · 오답노트 18개(영역: 선수 기록 9, 규칙 5 …)
최근 경기 10  [10-28 15:03 · 연습 · 2점 · 6타석 · 정답 4] …  (누르면 §3-3 경기 상세)
관리자 기록  10-28 15:20 상세 열람 · 10-28 15:21 이메일 보기
조치  [닉네임 초기화]* [계정 삭제]*        * 이용약관 확정 뒤
```

- 읽기: 프로필 1 + 누적 1 + 오답 개수(집계 1) + 최근 경기 10 + 관리자 기록 몇 개 ≈ **15**
- **열 때마다 `adminLogs`에 "상세 열람"**, 이메일 보기는 따로 한 번 더(1차와 같음)
- **조치는 정해진 것만**: 닉네임 초기화(부적절한 닉네임 — 다음 접속 때 다시 정하게), 계정 삭제(1차 기획 §5.4). 둘 다 이용약관
  근거가 먼저라 약관 확정 전에는 **본인 요청·만 14세 미만 의심만**. 기록·점수 수정은 없다
- **메모 칸은 두지 않는다**: 자유 메모는 새 개인정보 처리(처리방침 개정)이고 쌓이기 쉽다. 필요한 사실은 정해진 조치의 사유 선택으로만

## 3. 오늘 경기 확인

### 3-1. 요약(지금도 가능 — 숫자만, 개인 정보 없음)

| 항목 | 계산 | 읽기 |
|---|---|---|
| 경기 수(연습·레벨 테스트) | `games` 묶음 `count()` + `mode` 조건 | 집계 2 |
| 평균 득점·평균 타석 | 집계 `average('runs')`·`average('pa')` | 집계 2 |
| 홈런·정답 | 경기 문서에 홈런 수·정답 수 필드가 없다 → **스냅샷(PC 작업)에서만** 계산, 오늘은 목록에 읽은 만큼만 | — |
| 회원/비회원 비율 | 경기 문서에 구분이 없다 → 목록에 읽은 것으로 표본 비율, 정확한 값은 스냅샷 | — |
| 시간대별 경기 수 | 0~23시 24칸, 오늘 목록(최대 300개)으로 | 목록 읽기 |

집계 쿼리(`getAggregateFromServer`)는 색인 항목 1,000개당 읽기 1이라 싸다. 경기 문서에 **합계용 필드(홈런 수·정답 수·회원 여부)를
더하면** 오늘 숫자도 집계로 정확해진다 — 규칙(필드 목록·값 검사)과 저장 코드를 함께 바꾸는 일이라 §10의 2-D에서 결정.

### 3-2. 최근 경기 목록(11-03부터 — 누가 했는지가 보이므로)

`games` 묶음 `createdAt` 내림차순 50개씩. 줄: 시각 · 회원 닉네임 또는 "비회원 uid 앞 6자리" · 모드 · 득점 · 타석 · 정답 수 ·
응답 시간 합 · 홈런 수(경기 문서의 `atBats`에서 계산).

- 필터: 모드, 회원/비회원, 득점 3점 이상, 이상 징후만
- 닉네임은 화면에 보이는 50개의 uid로 프로필을 읽어야 한다 → 읽기 최대 +50. **기본은 uid 앞자리만**, "닉네임 보기"를 누르면 읽기

### 3-3. 경기 상세

타석별 표: 순서 · 문항(영역·난이도·질문 앞부분, 문항 ID) · 고른 답/정답 · 맞음 · 응답 시간 · 결과(안타·홈런…) · 타점. 문항은
앱에 들어 있는 문제은행으로 보여 주므로 **읽기 0**(경기 문서 1개는 목록에서 이미 읽음).

### 3-4. 이상 징후(관찰만)

| 징후 | 기준(처음 값 — 실제 분포 보고 조정) | 뜻 |
|---|---|---|
| 너무 빠름 | 한 경기 평균 응답 0.6초 미만 + 정답률 90% 이상 | 자동 입력 의심 |
| 너무 많음 | 회원 한 명이 하루 40판 넘게 | 무료 한도를 혼자 쓰는 중 |
| 비회원 급증 | 한 시간에 새 익명 계정 30개 넘게(계정 사본·스냅샷) | 하루 3판 우회 — App Check 결정 근거 |
| 같은 응답 반복 | 한 경기 모든 답이 같은 보기 | 장난·자동 입력 |

- **기록을 지우거나 고치지 않는다**(비공식이고, 판단 근거가 기기 데이터뿐). 표시하고 숫자를 모아 App Check·이용 제한(약관 뒤) 결정에 쓴다
- 기준은 `src/lib/admin/` 순수 함수 + 단위 테스트(1차의 판별 함수와 같은 방식)

### 3-5. 문항 품질(스냅샷)

어제·7일: 정답률 낮은 문항 TOP 10, 시간초과 많은 문항, 영역·난이도별 정답률. 문항 ID → 문항 내용(앱 문제은행). 고칠 문항은
`../data/*.csv`를 고쳐 다시 배포(지금 절차 그대로).

## 4. 대결 방 확인

### 4-1. 목록

| 열 | 출처 |
|---|---|
| 코드 · 상태(대기·진행·끝) | 방 문서 |
| 만든 시각 · 지난 시간 | `createdAt` |
| 인원/정원 · 문제 수 | `playerIds.length`/`maxPlayers` · `questionIds.length` |
| 방장 | 방장 자리의 이름표(11-03부터) — 그 전에는 "방장 uid 앞자리" |
| 진행률 | 자리들의 답 수 합 ÷ (인원 × 문제 수) — 상세를 열 때만 계산 |

- 탭: 대기 · 진행 · 끝 · 24시간 지남(정리 작업이 03:30에 지울 방)
- **살펴볼 것 표시**: 진행인데 10분 넘게 새 답이 없음(멈춤), 대기인데 1시간 넘게 시작 안 함, 24시간 지남
- 읽기: 방 목록 30개씩 = 30. 자리는 상세에서만

### 4-2. 상세

참가자별: 이름표 · 점수 · 정답/답한 수 · 마지막 답 시각 · 순위. 문항 목록(앱 문제은행으로 — 읽기 0).

- **실시간 구독을 하지 않는다**: 관리자가 보는 동안 방 안 사람 수 × 답 수만큼 읽기가 늘기 때문. "새로고침" 버튼, 진행 중인 방만
  "30초마다 자동"을 켤 수 있게(최대 10분 뒤 꺼짐)
- 읽기: 방 1 + 자리 N(최대 10)

### 4-3. 조치

| 조치 | 하는 일 | 근거·전제 |
|---|---|---|
| 지난 방 지금 정리 | 24시간 지난 방·자리 삭제(정리 작업과 같은 기준) + 기록 | 처리방침의 보관 기간 그대로 — 지금도 가능 |
| 방 닫기(관리자) | 대기·진행 중인 방을 닫음(방·자리 삭제) + 기록. 참가자 화면은 "방이 없어요" | 부적절한 이름표 등 — **이용약관 근거 뒤** |
| 이름표 가리기 | 하지 않는다 | 방은 24시간 뒤 지워지므로 닫기로 충분 |

규칙: 방·자리 삭제에 `isAdmin()` 추가, 관리자 기록과 한 묶음.

## 5. 공통

- **기간·시각**: 모두 한국 시간. "오늘" = 한국 시간 0시부터
- **비공식 표시**: 경기·점수·대결 화면 위에 "기기에서 채점한 비공식 기록"
- **내보내기(CSV)는 두지 않는다**: 개인 정보가 화면 밖으로 나가면 접속기록·파기 관리가 안 된다. 숫자 요약만 화면 캡처로
- 관리자 기록에 남길 행동: 회원 상세 열람, 이메일 보기, 경기 목록의 닉네임 보기, 방 상세 열람(이름표가 보이므로), 모든 조치
- 화면 접근성: 1차와 같이 표에 머리글, 배지는 글자로(색만으로 구분하지 않음), axe 검사

## 6. 먼저 고칠 것 — 대결 방·자리 목록 좁히기

지금 규칙: `rooms/{code}`와 `rooms/{code}/players/{uid}`가 `allow read: if signedIn()`. `read`는 **하나 읽기와 목록 읽기를 모두**
허락하므로, 로그인한 누구나(비회원 포함) 모든 방 코드와 모든 자리(이름표·점수)를 훑을 수 있다. 앱은 방 목록을 쓰지 않는다.

| 대상 | 바꾼 뒤 |
|---|---|
| 방 하나 읽기(`get`) | 로그인한 누구나 — 코드로 들어가기·구독(지금 그대로) |
| 방 목록(`list`) | **관리자만** |
| 자리 목록(`list`) | 그 방 명단에 있는 사람(대결 화면의 자리 구독) + 관리자 — 규칙의 `get()` 1번(읽기 1)이 든다 |

규칙 테스트(목록 거절·명단 안 사람 허용·관리자 허용)와 대결 E2E로 확인. 처리방침 변화 없음(줄이는 쪽).
