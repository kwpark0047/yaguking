# 메인의 "이렇게 놀아요"·"최신 소식"

2026-10-29. 처음 앱(Next.js) 메인의 두 구역을 웹앱으로 옮겼다. 운영자 결정: **서비스 소식 + 매일 자동 확인**(리그 소식 자동 수집 아님).

## 1. 이렇게 놀아요

처음 앱의 세 단계를 이 앱의 실제 규칙으로 고쳐 옮겼다(처음 앱의 "회원 3이닝·업적 카드"는 이 앱에 없다): 문제 하나 = 공 하나, 15초 →
빨리 맞히면 홈런·틀리거나 시간 초과면 아웃 → 3아웃이면 끝·박스스코어·찬스 이벤트. `src/components/home/HowToPlay.tsx`(글자만, 읽기 없음)

## 2. 최신 소식

- **무엇**: 야구왕 서비스 소식(업데이트·안내·이벤트). KBO 경기 결과·순위 같은 리그 소식은 **데이터 이용 허락 전까지 자동으로 가져오지 않는다**
  (koreabaseball.com은 사전 동의 없는 자동 수집 금지 — 처음 앱 `src/content/news.ts` 머리말과 같은 원칙). 처음 앱의 글은 처음 앱에만 있는 기능
  (업적 카드·선수 카드·화면 스타일)이라 옮기지 않고, 이 앱의 실제 기능으로 처음 글 5개를 새로 썼다(`ops/news-seed.json`)
- **쓰기**: 관리자 사이트 "최신 소식"(`src/admin/pages/NewsPage.tsx`) — 제목·날짜(이날부터 보임)·분류·요약·본문·**출처 이름·https 주소**가 모두 있어야
  저장된다. 글은 `adminConfig/news` 한 문서(화면 읽기 1), 쓰기·고치기·지우기는 관리자 기록에 남는다
- **올리기 = 매일 자동 확인**: 운영자 PC 매일 작업(`ops/run-cleanup.cmd` → `admin-cli news`, `ops/news.mjs`)이 글마다
  1. 칸 모양(길이·분류·달력에 있는 날짜·https 주소)
  2. **날짜**: 오늘 이하만 올린다. 미래 날짜는 예약(그날 새벽에 올라감), 1년 지난 글은 내린다
  3. **출처**: 주소가 실제로 열리는지(HEAD, 안 되면 GET, 10초, 2xx·3xx)
  를 확인해 **통과한 글만** 공개 문서 `public/news`(최신순 30개)에 쓴다. 이유는 `adminConfig/news.checks` → 관리자 화면에 "앱에 올림 / 올리지 않음 — 이유"
- **보기**: 메인 "최신 소식"(최근 3개, 글이 없으면 구역 없음), `/news`(전체·본문·출처 링크·날짜). 공지처럼 **Firestore SDK 없이** REST로 읽고 10분 기억(읽기 1)
- 규칙: `adminConfig/news`는 관리자만(글 목록 50개까지, 확인 결과 `checks`는 못 바꿈), `public/news`는 누구나 읽기·아무도 쓰기 불가(운영자 PC만)
- 앱 다시 배포 없이 반영된다. 바로 올리고 싶으면 운영자 PC에서 `node ops\admin-cli.mjs news --project=yaguking-bc25c`

## 3. 처음 배포할 때

```
npx firebase deploy --only firestore:rules --project prod
node ops\admin-cli.mjs news --project=yaguking-bc25c --seed=ops\news-seed.json   # 글이 없을 때만 처음 글을 넣고 바로 확인
npx firebase deploy --only hosting:app,hosting:admin --project prod
```
