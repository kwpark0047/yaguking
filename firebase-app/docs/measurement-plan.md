## 0. main의 분석 모듈을 그대로 쓰지 않는 이유

| 문제 | 내용 |
|---|---|
| 처리방침과 어긋남 | 회원·비회원 uid, 방문 경로, 유입 정보(UTM), 이전 페이지 주소를 이벤트마다 Firestore에 남긴다 — 처리방침은 "방문 분석 도구를 쓰지 않는다", 수집 항목에도 없다 |
| 동작하지 않음 | `collection(db, 'analytics', 'events')`는 Firestore가 허용하지 않는 경로(짝수 단계) — 첫 이벤트에서 오류 |
| 맞지 않는 가정 | 이 앱에 없는 카카오 로그인, 서비스 계정 키를 배포 서버에 두는 절차(`FIREBASE_ADMIN_SETUP.md` — Spark·서버 없음 구조와 다름) |
| 지금 필요한 것보다 많음 | 이용자가 하루 0~5명인 단계에서 이벤트마다 기록하면 개인정보만 늘고 얻는 판단은 같다 |

다시 쓸 것: UTM 표준(마케팅 문서 §9), `utm.ts`의 주소 읽기 방식, 이벤트 이름 목록(퍼널 단계 이름으로).

## 2. 3단계

### 1단계 — 운영자 PC 주간 퍼널(처리방침 개정 필요 없음, 바로 가능)

- 0시 작업(`daily`)에 붙인다: 지난 7일 **새로 온 계정 → 첫 경기 완료 → 다음 날 재방문 → 가입 → 만 14세 확인·프로필** 단계별 사람 수와 비율, **주간 게임 완료 고유 사용자**(회원·비회원 따로)
- 결과는 수만 `adminDaily/{날짜}`에(사람을 가리키지 않음). 관리자 대시보드 "어제·최근 7일"에 퍼널 막대 하나
- 이미 처리방침에 있는 정보(계정·경기 기록)로 이미 있는 목적(서비스 운영 관리)에 쓰는 계산 — 새 수집 없음
- 비용: 읽기 = 주간 경기 수 + 계정 사본(이미 읽는 것), 쓰기 0(하루 요약에 합침)

### 2단계 — 유입 경로(처리방침 개정·7일 전 공지 뒤)

- 홍보 링크에 정해진 UTM만 붙인다(마케팅 문서 §9 표준). 앱은 **처음 들어온 주소의 `utm_source`·`utm_campaign`만** 읽어 이 기기에(세션 동안) 둔다
  - 출처는 정한 목록만(예: `instagram`·`threads`·`x`·`openchat`·`community`·`share`·`toss`), 그 밖은 `etc` — 아무 글이나 저장되지 않게
- **첫 경기를 시작해 계정이 생길 때 한 번만** `users/{uid}/meta/acquisition` = `{ source, campaign, day }`를 쓴다(쓰기 1, 처음 한 번)
  - 규칙: 본인만, 만들기만(고치기·덮어쓰기 금지), 칸 3개, 출처는 목록 안, 캠페인 40자, 날짜는 서버 기준 오늘
  - 이전 페이지 주소·경로·브라우저 정보는 **모으지 않는다**
- 앱 안 공유 링크(오늘의 1이닝 결과, 친구 대결 방)에는 `utm_source=share`·`utm_campaign=daily|room`을 붙여 "친구가 데려온 사람"을 센다
- 1단계 퍼널을 **출처별로** 나눠 보여 준다(출처마다 사람 수가 3명 미만이면 "3명 미만"으로만 — 작은 수로 사람을 짐작하지 않게)
- 보관: 계정이 지워질 때 함께(비회원은 30일 쓰지 않으면 정리 작업이 지운다, 회원은 탈퇴 때 — `deleteUserRecords` 목록에 `meta`)

### 3단계 — 보류: Firebase Analytics(GA4)·이벤트마다 기록

- GA4는 무료지만 광고 식별자·쿠키·외부 스크립트(CSP), 동의 안내, 처리방침의 "방문 분석 도구 없음"을 바꾸는 큰 개정이 필요하다
- **주간 게임 완료 사용자가 100명을 넘고**, 1·2단계로 답하지 못하는 질문이 생기면 다시 판단한다

## 3. 처리방침 개정 문안(2단계, 초안)

- 처리 목적에 더함: "서비스 홍보 효과 측정 — 이용자가 처음 들어온 홍보 링크의 출처별 이용 현황을 합계로 확인"
- 수집 항목에 더함: | 이용 기록(유입) | 처음 들어온 홍보 링크의 출처·캠페인 이름, 그날 날짜(링크에 표시가 있을 때만) | 처음 경기를 시작할 때 자동 생성 |
- 보관: "계정이 삭제될 때 함께 삭제(비회원은 30일 동안 쓰지 않으면 삭제)"
- 기기 저장 목록에 더함: `yk_utm` — 처음 들어온 홍보 링크의 출처·캠페인(이번 방문 동안만, 창을 닫으면 지워짐)
- 바뀌지 않는 것: 외부 분석 도구·광고 네트워크를 쓰지 않음, 제3자 제공·위탁·국외 이전 그대로
- 변경 사항 안내 문구: "홍보 링크로 들어온 경우 그 링크의 출처를 기록해 홍보 효과를 합계로 확인합니다. 이전에 본 페이지 주소나 기기 정보는 모으지 않습니다."

## 5. `main`의 분석 모듈 처리

- 운영 브랜치(`feat/p1-one-inning`)에는 합치지 않는다. 2단계를 만들 때 `utm.ts`의 주소 읽기만 옮겨 고쳐 쓴다
- `main`에서 되돌릴지(4c7bc3c의 `firebase-app` 부분 되돌리기)는 그 브랜치에서 원래 앱 작업을 하는 쪽과 함께 정한다(지금 `C:\kbo261023`에 커밋 안 된 작업이 있다)
