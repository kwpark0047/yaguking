# 야구왕 Firebase판 — 데이터 구조 (2단계)

- 작성: 2026-10-26 · 대상: Firebase **Spark(무료)** — Firestore + Auth + Hosting만
- 규칙: `firestore.rules` · 테스트: `tests/rules/*.test.ts`(44개, Firestore 에뮬레이터)
- 문서 모양(TypeScript): `src/lib/data/types.ts` · 문서 ID 계산: `src/lib/data/keys.ts`

## 0. 원칙

1. **서버 코드가 없다.** 보안 규칙이 유일한 서버 쪽 방어선이다. 규칙은 **주인·모양·범위·
   서버 시각**을 지킨다. 점수의 "정답 여부" 자체는 기기가 계산하므로 지킬 수 없다
2. 그래서 Firestore에 남는 점수·기록은 **전부 비공식**이다. 공식 랭킹·공식 XP·RP는 신뢰할
   수 있는 판정 주체가 생길 때까지 만들지 않는다(16 문서 7단계)
3. **무료 한도**(하루 읽기 5만·쓰기 2만·삭제 2만, 저장 1 GiB)를 먼저 계산하고 설계한다.
   규칙 안의 `get()`·`exists()`도 읽기로 센다
4. 시각은 모두 **서버 시각**(`request.time`, `serverTimestamp()`)이다. 기기 시계를 믿지 않는다

## 1. 문항은 Firestore에 없다

문제은행 505문항은 `data/*.csv` → `scripts/build-questions.mjs` → `src/content/questions.generated.json`
(압축 약 42 KB)으로 **앱 묶음에 들어간다**. 경기를 시작할 때만 불러온다.

| | Firestore에 둘 때 | 정적 JSON(채택) |
|---|---|---|
| 문항 읽기 비용 | 사용자 1명 첫 방문에 최대 505읽기 → 하루 약 100명이면 한도 | **0** |
| 정답 노출 | 규칙으로 숨겨도 즉시 판정하려면 결국 기기로 와야 한다 | 묶음에 포함 |
| 갱신 | 콘솔·스크립트 | `npm run content:build` 후 다시 배포 |

**정답이 기기로 내려간다**(누구나 문제은행을 복사할 수 있다). 비공식 경기에서는 감수한다.
문항 ID는 본문 해시(`q` + 12자리)라 CSV를 다시 만들어도 같은 문항은 같은 ID다.
보기 섞기는 기존 앱과 같아 정답 위치 분포가 같다(A147·B108·C140·D110 — 단위 테스트가 확인).

## 2. 컬렉션

| 경로 | 누가 | 쓰기 시점 | 주요 규칙 |
|---|---|---|---|
| `users/{uid}` | 회원 본인 | 만 14세 확인(생성), 온보딩·설정·레벨 테스트(갱신) | 생성은 확인 시각=서버 시각만. 갱신 가능 필드: 닉네임·최애 구단·최애 선수·레벨 테스트·갱신 시각 |
| `nicknames/{소문자}` | 확인 회원 | 닉네임 바꿀 때(프로필과 한 묶음) | 대소문자 무시 유일. 프로필 닉네임과 예약이 같은 묶음에서 맞아야 함 |
| `users/{uid}/games/{id}` | 본인(비회원·확인 회원) | **경기 끝날 때 1번** | 수정 불가. 모드 practice·levelTest만. 타석 수 = 배열 길이. 생성 시각=서버 시각. 찬스 이벤트 결과 `events`(있을 때만, 최대 2개) |
| `users/{uid}/daily/{KST일}` | 비회원 본인 | 비회원 경기마다(경기와 한 묶음) | 오늘(서버 기준 KST) 문서만, 1씩만, 최대 3 → **비회원 하루 3경기** |
| `users/{uid}/summary/main` | 본인 | 경기마다 | 경기 수는 1씩만 증가, 안타≤타수≤타석, 홈런≤안타 |
| `users/{uid}/wrongNotes/{questionId}` | 본인 | 틀렸을 때·복습했을 때 | 문서 ID=문항 ID, 단계 0~4, 미래 시각 금지 |
| `rooms/{6자 코드}` | 로그인한 누구나(비회원 포함) | 만들기·참가·나가기·시작·종료 | 코드=문서 ID(중복 생성 불가). 참가는 자기 uid만 끝에 추가·정원 이내, 나가기는 대기 중 자기만(방장 제외 — 방장은 방을 닫는다). 방장만 시작(2명 이상)·종료 |
| `rooms/{코드}/players/{uid}` | 참가자 본인 | 참가, 문항마다 답 1개 | 명단에 있어야 자리 생성. 경기 중에만, 답은 한 번에 하나씩만 |
| `nicknames/{소문자}` 목록 | 관리자 | — | 하나씩 확인은 로그인한 누구나, 목록·앞글자 검색은 관리자만(2026-10-27 좁힘) |
| `notices/{id}` | 관리자 | 공지 쓰기 | 제목 1~80자, 본문 2000자, 끝 > 시작, 작성자·갱신 시각 강제 |
| `public/home` | **누구나 읽기**, 관리자 쓰기 | 공지를 고칠 때 같은 묶음으로 | 공지 20개까지, 필드 notices·updatedAt만 |
| `adminLogs/{id}` | 관리자 | 열람·이메일 보기·공지·동기화 요청 | 만들기만(고치기·지우기 불가), 작성자·서버 시각 강제 — 접속기록 2년 보관(법정 1년 이상, 정리 작업이 지난 것을 지움) |
| `adminTasks/{id}` | 관리자(요청) | 운영자 PC가 처리 | 1차는 syncAccounts만, 상태는 pending으로만 만들기 |
| `adminViews/{화면}` | 관리자 읽기·쓰기 | "새로 만들기" | 화면을 열 때 읽는 보기 하나(JSON). 정해진 6개 이름만, 쓴 사람·서버 시각 강제 — docs/admin-dashboard-plan.md |
| `accountMirror/{uid}`, `adminStats/accounts` | 관리자 읽기 | 운영자 PC 동기화만 | 회원(이메일·구글) 계정 사본, 비회원은 개수만 |

관리자 = 토큰 표시 `admin` + 이메일 인증 + **구글로 로그인한 세션**(`isAdmin()`). 관리자는 회원의 프로필·경기·누적·오답을 **읽기만**
한다(1차 — 삭제는 다음 단계). `docs/admin-plan.md`

여기 없는 경로는 모두 막힌다.

### 2.1 레벨 테스트

`users/{uid}.levelTest`에 **한 번만** 남는다(이미 있으면 바꿀 수 없음). 경기 기록은
`games`에 `mode: 'levelTest'`로 따로 남는다. 등급 1~5 = 맞힌 수 구간(PRD: 0~5 → 1, 6~9 → 2, 10~13 → 3,
14~17 → 4, 18~ → 5 — 규칙이 일치를 검사), 맞힌 수 ≤ 문항 수.

### 2.2 최애 선수

**선수 DB를 두지 않는다.** 이름을 자유 입력으로 최대 3명(각 1~20자) 받는다. 선수 명단은
KBO 기록 데이터라 이용 허락 전에는 수집·보관하지 않는다(13 문서).

## 3. 비용 추정 (무료 한도 기준)

| 행동 | 읽기 | 쓰기 |
|---|---|---|
| 앱 열기(회원) | 프로필 1 + 공지 묶음 1 | 0 |
| 앱 열기(비회원·처음) | 공지 묶음 1(Firestore SDK 없이 REST) | 0 |
| 개인 경기 1판(회원) | **0** + 규칙 get 1~2 | 경기 1 + 누적 1 + 오답 0~3 (증가 연산 — 읽지 않음) |
| 개인 경기 1판(비회원) | 남은 판 1 + 규칙 get 1~2 | 경기 1 + 카운터 1 + 누적 1 + 오답 0~3 |
| 레벨 테스트(회원 1회) | 저장 뒤 프로필 1 + 규칙 get 1~2 | 경기 1 + 프로필 1 + 오답 0~20 |
| 오답노트 화면 | 노트 수(복습 시각 순 30개씩, "더 보기") | 0 |
| 오답 복습 1문제 | 0 | 노트 1 |
| 친구 대결 10문항 × N명 | 각 사람이 답할 때마다 N명에게 1읽기 + 규칙 get 1 → 약 10·N² + 10·N | 약 10·N + 시작·종료 2 |

- 개인 경기는 판당 읽기 0~1(+규칙 get)·쓰기 5~6 → 하루 쓰기 2만이면 **약 3,300판**. 측정값은 `docs/usage-report.md`
- 친구 대결은 인원의 제곱으로 읽기가 는다: 4명 160읽기, 10명 1,000읽기 → **10명 방은
  하루 50판이면 읽기 한도.** 기본 정원 4명, 10명은 고를 때 사용량 안내를 띄운다(5단계)
- 경기 기록 문서는 판당 약 2 KB → 1 GiB에 약 50만 판

## 4. 무료 플랜이라 생기는 빈칸

- **자동 삭제(TTL)는 유료.** 끝난 방·오래된 비회원 기록은 저절로 지워지지 않는다 →
  `ops/cleanup.mjs`(8단계)가 관리자 권한으로 지운다 — 24시간 지난 방·주인 없는 자리·30일 쓰지 않은 비회원(`docs/deploy.md` §6)
- **익명 계정은 자동 삭제되지 않는다.** 비회원 하루 3경기 제한은 익명 계정을 새로 만들면
  우회된다. 계정 생성은 Auth가 IP당 시간당 100개로 막는다. 더 막으려면 App Check(무료 월 1만 건)
- 규칙은 배열 안의 각 항목을 검사하지 못한다(반복문 없음). 경기 기록의 타석 배열은 **길이만**
  검사한다
