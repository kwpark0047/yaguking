### 지킨 제약

- Supabase·Vercel·유료 API·유료 호스팅을 쓰지 않는다. **Blaze로 바꾸지 않는다**, Cloud Functions 없음
- 실제 KBO 기록은 이용 권한을 확보하기 전까지 자동 수집하지 않는다(문제은행은 직접 만든 CSV)
- 기기가 계산한 점수는 공식 랭킹에 넣지 않는다
- 기존 파일을 임의로 지우거나 덮어쓰지 않는다, **실제 배포는 운영자 승인 뒤**

## 2. 구조

```text
 이용자 브라우저 ─┬─ Hosting(yaguking)        정적 화면 + 문제은행 JSON(1,134문항, 문항 읽기 0)
                  ├─ Firebase Auth             이메일·구글·익명
                  └─ Firestore(서울)  ◀── firestore.rules = 유일한 서버 쪽 방어선
 관리자 브라우저 ─┬─ Hosting(yaguking-bc25c-admin)  강제 CSP, 저장·색인 금지
                  └─ Firestore(관리자 규칙)
 운영자 PC(Windows) ── 예약 작업 매일 0시(11-02부터): ops/run-cleanup.cmd(관리 SDK, 운영자 인증)
                       정리 → 대기 작업 → 계정 동기화 → 하루 요약 → 공식전 채점·출제 → 소식 확인 → 월간 등수
                     └ ops/admin-cli.mjs: 관리자 표시, 계정 사본 동기화·대기 작업, 소식 처음 넣기
 예전 주소(기본 사이트 yaguking-bc25c) ── 301 → yaguking.web.app (구글 로그인 도우미 /__/ 는 그대로)
```

- **서버 코드가 없다**(Cloud Functions 없음). 서버가 해야 할 일은 ① 보안 규칙(주인·모양·범위·서버 시각) ② 운영자 PC의
  예약 작업으로 나눴다
- 화면: React 19 + Vite 8 + Tailwind 4, React Router 8. Firestore를 쓰는 화면은 들어갈 때 받는다(첫 화면에 SDK 없음)
- 폴더: `src/pages`(화면 16개) · `src/lib`(엔진·게임·대결·데이터·효과·관리자 판별) · `src/admin`(관리자 사이트) ·
  `ops`(운영자 PC 작업) · `scripts`(문제은행·글꼴·배경·엠블럼·배포 점검) · `tests`(unit·rules·ops·e2e)
- 기존 앱에서 가져온 순수 코드는 `COPIED_FROM.md`

## 9. 주요 결정과 이유

| 결정 | 이유 |
|---|---|
| 문항을 Firestore가 아니라 정적 JSON으로 | 문항 읽기 0(한도). 대신 정답이 기기로 → 경기는 비공식 |
| 비회원 → 가입을 계정 연결로 | uid가 그대로라 서버 "기록 승계" 없이 기록이 이어짐 |
| 정리 작업을 운영자 PC 예약 작업으로 | Cloud Functions·Blaze 없이, GitHub 위탁(처리방침 추가) 없이 |
| 관리자 사이트를 별도 주소로, 구글 로그인만 | 이용자 앱 묶음에 관리 코드가 섞이지 않게, 강제 CSP, 접속기록 |
| 회원 정보 열람은 개정 시행일부터 | 처리방침 개정 7일 전 공지 |
| 공지를 공개 문서 하나 + REST 1번 읽기로 | 앱 열 때 Firestore SDK 없이, 읽기 1 |
| 짧은 주소는 새 Hosting 사이트로(자체 도메인 대신) | 무료. 기본 사이트는 넘기기만, `/__/`(구글 로그인 도우미)는 넘기지 않음 |
| 배경·효과를 직접 그림 | 워터마크 있는 스톡 이미지는 쓰지 않음, 파일도 작음 |
| 공식 점수는 "오늘의 공식전"(운영자 PC 채점)과 출석만 | 연습 경기는 정답이 기기에 있어 조작할 수 있다 — 공식 랭킹에 넣지 않는다 |
| 같은 주소 로그인(authDomain = 앱 주소) | 사파리·최신 크롬·홈 화면 앱의 "missing initial state" 오류. 문제가 생기면 `SAME_ORIGIN_AUTH_ENABLED = false` |
| CI를 작업 브랜치에서 | 저장소의 기본 브랜치가 `feat/p1-one-inning`이고 `main`이 없다. 공개 저장소라 Actions 사용료 없음 |
| 문제은행을 B구간까지(법적 검토 전, 운영자 결정 11-01) | KBO_YaguKing_Docs 10 문서 §1.2: B(널리 공표된 역사적 사실)는 "법적 검토 후", C(선수별 시즌 수치)는 기록 DB 사용권 필요. B만 쓰고, 표 하나에서 통째로 옮기지 않고 사실마다 대조해 출처·확인일을 남겼다. C는 쓰지 않음 |
| 공식전 풀 사실은 앱 문제은행에서 뺀다 | 앱 묶음(공개)에서 공식전 답을 찾을 수 없게 — 본문뿐 아니라 해설에 드러나는 것까지 |
| 매일 작업 0시 + 채점 기다리기 | 운영자 요청. 23:59:59에 시작한 공식전 답이 0시 이후 최대 81초 들어오는데 채점은 한 번뿐이라, 그 시간을 기다린다 |
| 첫 문제만 20초, 판정에서 5초 빼기 | 경기 시작 직후 화면·문제에 적응할 시간. 판정까지 늘리면 첫 타석 홈런이 쉬워져 기록 기준이 흔들림 |
| 효과는 짧게·막지 않게·더 조용한 쪽으로 | 동작 줄이기·고대비·설정 존중, 결과는 글자로 먼저 |

| 의존성 경고 | `npm audit` 21건(높음 5). 높음은 모두 Firebase SDK(13.1.0, 최신)의 Firestore가 고정한 `@grpc/grpc-js ~1.9`(gRPC **서버** 쪽 문제). 브라우저 앱 묶음에는 grpc가 들어가지 않는다(빌드 결과 확인) — 테스트·운영자 PC(Node)에서만 쓰여 받아들임. Firebase가 올리면 따라 올린다 |
| 큰 묶음 | Firestore 묶음 546 KB(압축 163 KB), 문제은행 661 KB(압축 89 KB — 516문항 때 44 KB) — 게임 화면에 들어갈 때만 받고 1년 캐시 |
| 공용 기기 | 로그아웃해도 Firestore 오프라인 저장이 남는다(처리방침에 안내) — 로그아웃 때 지우는 기능은 후보 |
| KBO 데이터 | 실제 기록 자동 수집은 권리 확보 뒤(`../KBO_YaguKing_Docs_20261023` 12·13 문서) |

## 11. 처음 시작하는 사람에게

```bash
cd firebase-app
npm install
npm run dev
```

- 기본은 로컬 에뮬레이터 모드(`demo-yaguking`) — 실제 Firebase에 닿지 않는다. 전체 테스트에는 JDK 21이 필요하다
- 실제 프로젝트 설정은 `.env.production.local`(커밋 안 함). PowerShell에서는 `npx.cmd`·`npm.cmd`를 쓴다(스크립트 실행 정책)
- 화면 문구를 바꾸면 `npm run font:subset`(빌드가 자동으로 돌리지만, 단위 테스트는 커밋된 글꼴과 비교한다)
