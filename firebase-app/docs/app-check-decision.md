# App Check(비회원 하루 3판 우회 막기) — 판단 근거 (보류 권장)

2026-10-28. 비회원은 하루 3판인데, 브라우저 저장소를 지우거나 시크릿 창을 열면 **새 익명 계정**이 생겨 다시 3판을 할 수 있다.
보안 규칙은 계정마다 세므로 막을 수 없다. Firebase App Check는 "진짜 우리 앱에서 온 요청인지"를 확인해 자동화된 대량 요청을
줄이는 기능이다. 켤지 판단한다.

## 1. App Check가 막는 것과 못 막는 것

| | |
|---|---|
| 막는다 | 우리 앱이 아닌 스크립트가 Firestore·Auth를 직접 부르는 것(대량 계정 만들기·대량 쓰기) |
| **못 막는다** | 사람이 시크릿 창을 열어 다시 3판 하는 것 — 진짜 브라우저·진짜 앱이므로 통과한다 |

즉 "하루 3판 우회"의 대부분(사람이 창을 새로 여는 것)은 App Check로도 막히지 않는다. 막히는 것은 자동화된 남용이다.

## 2. 지금 켜지 않는 이유

1. **무료 한도·비용**: 웹의 App Check는 reCAPTCHA(v3 또는 Enterprise)로 확인한다. reCAPTCHA는 월 일정 건수(작성 시점 1만 건)까지
   무료이고, 넘으면 결제 계정이 필요하다 — 이 서비스의 원칙(유료 API·결제 없음)과 맞지 않는다. 확인 토큰은 보통 1시간마다
   새로 받으므로 하루 수백 명만 와도 한도에 가까워진다. (켜기 전 Google Cloud 콘솔에서 현재 무료 한도를 다시 확인할 것)
2. **처리방침 개정**: reCAPTCHA는 브라우저·기기 신호를 Google로 보낸다 — 처리 항목(기기 신호)과 목적(부정 이용 방지)을 처리방침에
   더하고 **시행 7일 전 공지**해야 한다
3. **정상 이용자 차단 위험**: 확인이 실패하면(광고 차단기·오래된 브라우저) 게임 저장이 거절된다
4. 지금 실제 이용 규모(계정 27개, 비회원 25)에서는 남용 신호가 없다

## 4. 다시 판단할 때(신호)

- "비회원 급증"이 며칠 이어지거나, 하루 쓰기가 무료 한도(2만)의 절반을 넘을 때
- 그때 순서: ① 콘솔에서 reCAPTCHA 무료 한도 재확인 ② 처리방침 개정안(기기 신호·부정 이용 방지) 공지(7일) ③ App Check를
  **모니터링 모드**로 켜서(거절하지 않고 기록만) 정상 요청 비율 확인 ④ 문제 없으면 Firestore·Auth에 적용
- 코드 준비 범위: `firebase/app-check`를 사이트 키가 있을 때만 불러오는 초기화 몇 줄(지금은 넣지 않음 — 쓰지 않는 코드)
