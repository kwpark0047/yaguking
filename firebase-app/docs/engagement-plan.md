# 참여 높이기 기획 — 누적 점수, 매일 출석, 월간 등수 (기획만)

2026-10-29. "게임 성적을 점수로 누적하고, 매일 출석·매월 등수 같은 이벤트로 참여를 높이자"는 운영자 요청에서 출발한다.

> **이 문서는 기획이다. 코드·규칙·배포는 바꾸지 않았다.** 만들기 전에 §9의 결정이 필요하다.
> 제약(그대로): Spark 무료만, Cloud Functions 없음, **기기가 조작할 수 있는 점수는 공식 랭킹에 넣지 않음**, 실제 KBO 기록 자동 수집 없음.

## 0. 핵심 판단 — 점수를 세 갈래로 나눈다

지금 경기 점수·XP는 **기기가 계산한다**(정답 묶음과 시계가 기기에 있다 — `docs/official-xp-rp.md` §1). 이 점수를 그대로 더해 월간 등수를
매기면, 기기에서 점수를 바꾼 사람이 1위가 된다. 그러면 성실하게 한 사람이 오히려 의욕을 잃는다. 그래서 점수를 셋으로 나눈다:

| 점수 | 무엇으로 | 누가 계산 | 믿을 수 있나 | 쓰는 곳 |
|---|---|---|---|---|
| **연습 점수** | 지금 경기(득점·안타·찬스 이벤트) | 기기 | ✗ 바꿀 수 있음 | **내 기록만**: 누적·이번 달·월간 목표 배지 |
| **출석 포인트** | 하루 한 번 출석 도장 | 보안 규칙(서버 시각) | ✅ 날짜를 지어낼 수 없음 | 월간 등수(1차부터) |
| **공식 점수** | 하루 한 번 "오늘의 공식전" | 운영자 PC 밤 작업(판정) | ✅ 정답이 기기에 없음 | 월간 등수(2차부터) |

- **월간 등수 = 출석 포인트 + 공식 점수.** 1차는 출석만으로 시작하고, 2차에 공식전이 붙으면 실력이 더해진다
- 연습 점수는 등수에 넣지 않는 대신 **개인 목표**로 쓴다("이번 달 연습 점수 3,000 달성" 배지). 남과 비교하지 않으니 바꿔도 얻는 것이 없다

## 1. 원칙

1. **매일 올 이유 하나.** 도장 한 번이면 끝나도록 3초, 단추 하나. 경기는 하고 싶을 때
2. **등수는 믿을 수 있는 것만.** 서버 시각이나 운영자 PC 판정을 거친 값만 등수에 넣는다
3. **명예 보상부터.** 칭호·배지·명예의 전당. 실물 경품은 연락처를 모으고 경품 고지를 해야 해서 따로 정한다
4. **무료 그대로.** 출석은 하루 쓰기 1번, 등수 화면은 읽기 1번. 등수 계산은 이미 돌고 있는 운영자 PC 매일 작업(03:30)에 붙인다
5. **회원만.** 출석·등수는 만 14세 확인 회원만 받는다. 비회원 기록은 30일 뒤 지워지고 닉네임도 없다. 비회원 화면에는 "가입하면 출석 도장"을 보여 준다

## 2. 매일 출석

### 화면
- 홈 맨 위에 **"오늘 출석" 카드**: 도장 단추 → 도장이 "쾅" 찍히는 효과(기존 효과·소리 장치, 동작 줄이기면 정지 화면) → "연속 3일째!"
- 이번 달 **출석 달력**(마이·홈 카드를 펼치면): 찍은 날은 우리 엠블럼 도장, 오늘은 빈 칸 깜빡임 없음(정지 테두리)
- 연속 출석 표시: 3·7·14·30일에 띠("7일 연속 출석!")

### 포인트

| 무엇 | 포인트 |
|---|---:|
| 출석 1일 | 10 |
| 7일 연속을 채울 때마다 | +30 |
| 그 달 개근(그 달 모든 날) | +100 |
| (2차) 오늘의 공식전 완주 | +20 |

- 한 달 최대 ≈ 310 + 30×4 + 100 = **530**(31일 달). 하루를 빠지면 연속은 끊기지만 그날까지 모은 포인트는 남는다
- 연속 보너스는 **밤 작업이 날짜로 다시 계산한다**(기기가 보낸 연속 일수는 화면 표시용)

### 데이터·규칙
- `users/{uid}/attendance/{YYYYMM}` — 한 달에 문서 하나: `days`(찍은 날 목록, 1~31), `updatedAt`
  - 만들기·고치기: 본인, 확인 회원, 문서 ID = **서버 시각으로 계산한 이번 달**(KST), 새 `days` = 이전 목록 + **오늘(서버 기준) 하나만**,
    이미 있는 날이면 거절, `updatedAt == request.time`. 지우기는 계정 삭제 때만
  - 기존 `kstDay()`(서버 시각 → 한국 날짜)를 그대로 쓴다. 기기 시계를 바꿔도 어제·내일 도장은 찍히지 않는다
- 비용: 회원 하루 **읽기 1(달력·오늘 찍었는지) + 쓰기 1**. 하루 쓰기 한도 2만 중 회원 1명당 1
- 남는 약점: 계정 여러 개. 공식전과 같은 한계라 확인 회원만 받고, 관리자 요약에서 같은 시각에 몰린 가입을 본다(비회원 급증 감시와 같은 방식)

## 3. 누적 연습 점수(내 기록)

- 지금도 `summary/main`에 경기 수·안타·홈런·XP가 쌓인다. 여기에 **이번 달 칸**을 더한다: `summary/main.month`(`YYYYMM`), `monthXp`, `monthGames`.
  달이 바뀌면 첫 경기에서 0부터 다시 시작한다(규칙: 달 키가 서버 기준 이번 달이어야 하고, 달이 같으면 늘기만 한다)
- 화면: 마이에 "누적 연습 점수 12,340 · 이번 달 1,820(경기 14판)". 경기 결과 화면에 "이번 달 +130"
- **월간 목표 배지**(개인): 이번 달 연습 점수 1,000 / 3,000 / 6,000, 이번 달 경기 30판. 기존 업적 카드(`src/lib/achievements`)에
  "이달의 목표" 줄로 붙인다. 기기 계산 — **비공식 표시**
- 추가 비용 없음(이미 매 경기 쓰는 누적 문서에 필드만 더함)

## 4. 월간 등수

### 계산 — 운영자 PC 매일 작업
- 지금 순서(정리 → 대기 작업 → 계정 동기화 → 하루 요약) 끝에 **`admin-cli monthly`**를 더한다:
  1. 이번 달 출석 문서를 모두 읽어(`collectionGroup('attendance')`, 문서 ID = 이번 달) 출석 포인트를 다시 계산한다(연속·개근 보너스 포함)
  2. (2차) 공식 점수를 더한다
  3. `leaderboards/{YYYYMM}` **문서 하나**에 쓴다: 상위 50명(닉네임·최애 구단·점수·출석 일수), 참여 인원, **점수별 인원 분포**, 기준 시각
- 매월 1일 작업은 지난달 등수를 **확정**한다(`final: true`, 이후 안 바뀜). 칭호를 준다: `users/{uid}/awards/{YYYYMM}`(운영자 PC만 쓰기, 본인·누구나 읽기)
- 운영자 PC가 꺼져 있던 날은 다음 실행에서 따라잡는다(처음부터 다시 계산하므로 빠진 날이 생기지 않음). 화면에 "어제 기준"이라고 적는다

### 화면
- 홈 카드 "이번 달 순위": 1~3위 닉네임, **내 순위**("23위 / 140명", 상위 16%)
  - 내 순위는 분포표와 내 출석 문서로 기기가 계산한다. 따로 읽지 않으므로 **읽기 1번**에 화면 하나
- 등수 화면(`/ranking`): 상위 50, 지난달 결과(확정), 내 칭호
- 동점은 같은 순위(공동 3위). 1차는 출석만이라 개근한 사람은 모두 공동 1위다. "개근상"으로 보여 주고, 2차에 공식 점수가 붙으면 순위가 갈린다

### 칭호(한 달 동안 닉네임 옆에)

| 조건 | 칭호 |
|---|---|
| 1위 | 이달의 야구왕(금) |
| 2~3위 | 이달의 올스타(은) |
| 4~10위 | 명예의 전당(동) — 홈에 다음 달 내내 이름 |
| 개근 | 개근상(달력 도장 금색) |

### 공개 범위
- 등수에는 **닉네임·최애 구단만** 보인다. 이메일·이름은 보이지 않는다. 설정에 **"등수에 내 닉네임 숨기기"**(숨기면 "익명 선수"로 표시하되 순위는 유지)
- 처리방침에 "월간 등수(닉네임·최애 구단·점수 공개, 숨기기 가능)"를 더하고 시작 7일 전에 공지한다

## 5. 오늘의 공식전(2차) — 실력이 등수에 들어가는 길

`docs/official-xp-rp.md`의 설계를 쓰되, 두 가지를 바꾼다:

| 원래 설계 | 바꾼 것 | 이유 |
|---|---|---|
| GitHub Actions 매시 판정 | **운영자 PC 매일 03:30 판정**(이미 도는 예약 작업) | 새 계정·키 설정이 필요 없다. 등수는 하루 단위라 결과가 다음 날 아침이어도 된다 |
| 10문제 | **5문제**(권장) | 운영자가 매달 쓸 문항 150개. 10문제면 300개 |

- 문제는 앱 묶음에 없는 **별도 문항**이고, 정답은 운영자 PC에만 있다. 문제는 하나씩 열리고, 답마다 서버 시각이 찍힌다(설계 §4, 에뮬레이터 확인 끝)
- 기존 문제은행 516문항은 이미 공개 묶음에 있어 쓸 수 없다. 새로 쓰거나 최신 경기 문항(사람이 확인해 쓴 것)을 공식전 먼저 쓰고 나중에 연습 문제로 푼다
- 공식 점수: 정답 100 + 빠르기 최대 50(설계 §5). 하루 최대 750 → 월간 등수는 실력이 크게, 출석이 작게 정한다
- 운영자 할 일이 생긴다: 매주 문항 35개 준비. 이 부담이 맞는지가 §9-3 결정이다

## 6. 이벤트 달력(운영)

| 이벤트 | 언제 | 내용 | 만드는 것 |
|---|---|---|---|
| **월간 시즌** | 매월 1일~말일 | 등수 시작·확정, 칭호 | 위 §4 |
| **출석 주간** | 달마다 한 주(운영자가 정함) | 출석 포인트 2배 | 밤 작업 설정값 `doubleDays`(관리자 사이트에서 날짜 입력) |
| **가을야구 주간** | 포스트시즌 기간 | 최신 경기 문항 먼저 내기, 홈 띠 | 이미 있는 공지 + 출제 우선순위 |
| **구단 대항전**(3차) | 월간 | 최애 구단별 팬 출석 합(1인 1구단, 첫 번째 최애) — "이번 달 출석 1위 팬덤" | 밤 작업에 구단 합계 한 줄 |
| **개막·올스타 특집**(3차) | 시즌 일정에 맞춰 수동 | 특집 문항 묶음 | 문항 작성 |

- 이벤트는 모두 **공지 + 설정값**으로 켜고 끈다(코드 배포 없이). 실물 경품 이벤트는 §9-4 결정 뒤

## 7. 비용(무료 한도 — 하루 읽기 5만·쓰기 2만)

| 행동 | 읽기 | 쓰기 |
|---|---|---|
| 출석 도장(회원 하루 1번) | 1(달력) | 1 |
| 홈 순위 카드 | 1(등수 문서) | 0 |
| 연습 경기 이번 달 누적 | 0 | 0(기존 누적 문서에 필드만) |
| 밤 작업 `monthly` | 출석 문서 = 이번 달 출석한 회원 수 | 등수 1 + (1일) 칭호 = 상위 10 |
| (2차) 공식전 5문제 | 약 13 | 약 6 + 판정 3 |

- 회원 1,000명이 매일 출석·순위 확인을 하면 읽기 2,000 + 밤 작업 1,000, 쓰기 1,000. 한도 안이다
- 밤 작업 읽기는 회원 수만큼 늘어난다. 1만 명을 넘으면 출석 문서를 날마다 바뀐 것만 읽도록 바꾼다(`updatedAt` 조건)

## 8. 만드는 순서

| 차수 | 내용 | 대략 |
|---|---|---|
| **1차** | 출석 도장(규칙·화면·달력·연속 띠), 이번 달 연습 점수와 목표 배지, 밤 작업 `monthly`, 월간 등수(출석), 홈 순위 카드·등수 화면, 닉네임 숨기기, 처리방침, 칭호 | 이틀 |
| 2차 | 오늘의 공식전 5문제(규칙·문항 하나씩 열기·운영자 PC 판정), 공식 점수를 월간 등수에 더하기, 관리자 사이트 공식전 문항 관리 | 사흘 + 운영자 문항 준비 |
| 3차 | 구단 대항전, 출석 주간 설정, 특집 문항, (결정 시) 경품 이벤트 | 하루 |

확인 방법: 규칙 테스트(어제·내일 도장 거절, 하루 두 번 거절, 남의 문서 거절, 비회원 거절, 달 바뀜), 운영 테스트(에뮬레이터에서 `monthly`
계산·동점·연속 보너스·확정 뒤 바뀌지 않음·따라잡기), E2E(도장 → 달력·띠, 순위 카드 읽기 1번, 숨기기), 사용량 측정.

## 9. 정해 주실 것

1. **월간 등수 기준** — **출석으로 시작하고 2차에 공식전 점수 더하기(권장)** / 연습 점수로 비공식 등수(권장하지 않음: 바꾼 점수가 1위가 되고, "조작 가능한 점수는 랭킹에 넣지 않는다" 원칙과 맞지 않음)
2. **출석 방식** — **홈의 도장 단추(권장: 찍는 재미)** / 앱을 열면 자동
3. **오늘의 공식전** — **5문제, 운영자가 매주 35문항 준비(권장)** / 10문제 / 공식전 없이 출석 등수만
4. **보상** — **칭호·배지·명예의 전당만(권장)** / 실물 경품(연락처 수집 동의·경품 고지·제세공과금 검토 필요)
5. **등수 닉네임 공개** — **기본 공개 + 숨기기 선택(권장)** / 기본 숨김
6. **구단 대항전** — **3차(권장)** / 1차에 함께
